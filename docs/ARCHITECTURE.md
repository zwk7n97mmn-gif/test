# 設計

中身を変えたい人向けの資料です。使うだけなら [SETUP.md](SETUP.md) と
[OPERATIONS.md](OPERATIONS.md) で足ります。

## 全体像

```
GitHub Actions (cron: 23:00 / 12:00 UTC)
        │
        └─ src/post.py
              ├─ tips.load_all()    content/tips/*.json を読む
              ├─ tips.validate()    壊れた投稿を本番前に止める
              ├─ state.load()       state/posted.json を読む
              ├─ tips.pick_next()   未投稿の 1 件を選ぶ
              ├─ bluesky.post()     AT Protocol へ
              ├─ xapi.post()        X API v2 へ
              └─ state.save()       履歴を書き戻す
                    │
                    └─ Actions が state/ をコミットして push
```

## ファイルの役割

| ファイル | 担当 |
|---|---|
| `src/post.py` | エントリポイント。選択 → 投稿 → 記録の順序と、失敗時の判断 |
| `src/tips.py` | コンテンツの読み込み・検証・出題順の決定 |
| `src/state.py` | `state/posted.json` の読み書き |
| `src/bluesky.py` | AT Protocol クライアント。リッチテキスト facet の生成を含む |
| `src/xapi.py` | X API v2 クライアント。OAuth 1.0a 署名を自前実装 |
| `src/textlen.py` | X / Bluesky それぞれの文字数計算 |
| `src/ai_assist.py` | Issue に返信する AI アシスタント（投稿とは独立） |

## 出題順の決め方

**同じ巡回の中では重複せず、巡回が変わると順序が変わる**、という 2 つを満たします。

順序は `tips.rotation()` が決めます。`random.Random(f"psych-tips-cycle-{cycle}")`
を種にしてシャッフルするので、**同じ巡回番号なら常に同じ順序**になります。

これが重要なのは、状態ファイルが壊れたときです。順序が乱数任せだと復元できませんが、
巡回番号から決定的に再現できるなら、`done_ids` さえ分かれば続きから再開できます。

`tips.pick_next()` は、この順序のうち未投稿のものを先頭から見て、
**直前と同じカテゴリを避けて**選びます。ただし残りが全部同じカテゴリなら
そのまま出します（カテゴリを揃えるより、投稿を止めないほうを優先する）。

全件出し切ると `state.record()` が巡回番号を 1 つ進め、`done_ids` を空にします。

## 状態ファイル

`state/posted.json`:

| キー | 意味 |
|---|---|
| `cycle` | 何巡目か。1 から始まり、一巡するごとに増える。順序の種を兼ねる |
| `done_ids` | この巡回で投稿済みの id。一巡すると空に戻る |
| `last_category` | 直前に投稿したカテゴリ。連続を避けるために見る |
| `history` | 投稿の記録。直近 400 件だけ残す（差分レビューを読める大きさに保つため） |

読み込みに失敗しても例外にはせず、初期値で続行します（`state.load()`）。
順序は決定的なので、最悪でも「1 巡目の最初から」に戻るだけで済みます。

## 文字数の数え方

X と Bluesky で数え方が違うため、両方を `src/textlen.py` に実装しています。

| | 上限 | 数え方 |
|---|---|---|
| X | 280 | weighted length。日本語などの全角圏は 1 文字 2、他は 1。日本語だけなら実質 140 字 |
| Bluesky | 300 かつ 3000 bytes | 書記素クラスタ数と UTF-8 バイト数 |

**X のほうが常に厳しい**ので、X を通れば Bluesky も通ります。

書記素クラスタは標準ライブラリだけでは UAX #29 を完全実装できないため、
結合文字と ZWJ を前の文字にくっつける近似を使っています。
絵文字の合字を含まない通常の日本語では正確に一致します。

Bluesky のハッシュタグと URL は「リッチテキスト facet」として位置を明示する必要があり、
**そのオフセットは文字位置ではなく UTF-8 バイト位置**です。日本語では両者が大きく
ずれるので、`bluesky.build_facets()` は必ずバイト単位で数えています。

## 失敗したときの扱い

| 状況 | 動き |
|---|---|
| 片方だけ失敗 | もう片方は投稿する。状態は更新する（消費される） |
| 両方失敗 | 状態を更新しない。その豆知識は次回に持ち越す |
| X が月間上限 | 失敗ではなく「見送り」。ワークフロー自体は成功扱い |
| 認証情報が片方だけ | 設定済みのほうにだけ投稿する |
| コンテンツの検証エラー | 1 件も投稿せず終了する（壊れた投稿を出さない） |

## 設計上の約束

守っている前提です。変更するときはここも一緒に更新してください。

1. **投稿経路に依存パッケージを増やさない。** `src/post.py` から辿れる範囲は
   Python 3.11 標準ライブラリだけで動きます。サーバーもデータベースも要りません。
   （唯一の例外が `src/ai_assist.py` で、これは投稿から独立しているため
   定期投稿には影響しません）
2. **状態は Git に置く。** リポジトリ自体が投稿ログを兼ねます。
   履歴を見れば「いつ何を出したか」がすべて残ります。
3. **順序は決定的にする。** 状態が失われても再現できる形にしておきます。
4. **壊れたコンテンツは本番前に止める。** 検証は CI と投稿直前の両方で走ります。
