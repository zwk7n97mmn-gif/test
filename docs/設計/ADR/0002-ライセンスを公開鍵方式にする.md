# ADR-0002: ライセンスを公開鍵方式にする

- 日付: 2026-08-20
- 状態: 有効

## 背景

買い切りのダウンロード販売で、購入者にキーを渡して制限を外したい。
サーバーを持たない方針（[ADR-0001](0001-単一HTMLファイルで配布する.md)）のため、認証サーバーは使えない。

## 選択肢

| 案 | 評価 |
|---|---|
| 共通鍵（HMAC）でキーを作る | 製品の中に秘密が入る。解析すれば誰でもキーを量産できる。却下 |
| 認証サーバーへ問い合わせる | 通信が発生し「外に出さない」という売りが崩れる。サーバー障害が販売事故になる。却下 |
| **公開鍵署名（P-256）** | 製品に入るのは公開鍵だけ。キーの偽造は秘密鍵なしには不可能。採用 |

## 判断

P-256（ECDSA / SHA-256）の署名を使う。秘密鍵は販売者の手元だけに置き、
製品には公開鍵を 1 行だけ埋め込む（`keygen.py init` が書き込む）。

外部ライブラリは使わず、Python 側（署名）と JavaScript 側（検証）を両方自前で実装する。
両者が一致することは、実際に鍵を作って突き合わせるテストで毎回確かめる。

## 守る範囲

**守る**: 第三者による偽造キーの流通。
**守らない**: 購入者本人が HTML を書き換えて制限を外すこと。

後者はテキストファイルである以上、技術的に防げない。使用許諾契約書で扱う。

## 帰結

- 認証のための通信が完全に不要になった。オフラインでも、10 年後でも動く
- 秘密鍵の管理が、事業の生命線になった。失うとキーを発行できず、作り直すと発行済みのキーが全部無効になる
  - → `.gitignore` での除外、配布物への混入検査（`build.sh` と CI）、手順書での注意喚起で守る
- 同じ仕組みを拡張パッケージの署名にも使い回せた（[ADR-0003](0003-拡張を署名つきパッケージにする.md)）
