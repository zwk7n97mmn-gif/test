# セキュリティ設計

何から守り、何は守らないかを、はっきり書いておきます。
「守っていない」ことを隠すほうが危険だからです。

## 前提

- 製品は購入者の端末で動く HTML ファイル 1 つ。サーバーはありません。
- 通信を一切行いません（外部リソースの読み込みもありません）。
- 攻撃者は、配布された HTML とパッケージを自由に読めます。

## 1. ライセンスキー

**守ること: 販売者以外がキーを作れないこと。**

- キーは P-256（楕円曲線）の署名つきです。署名できるのは秘密鍵を持つ販売者だけです。
- 製品に入っているのは**公開鍵だけ**です。解析しても新しいキーは作れません。
- 検証は端末内で完結します。認証サーバーはありません（＝落ちない、通信もしない）。

**守らないこと: 購入者が製品を書き換えて制限を外すこと。**

HTML はテキストです。書き換えれば検証を無効にできます。これは
「サーバーを持たない・通信しない」ことと引き換えです。
守っているのは*偽造キーの流通*であり、購入者本人による改造ではありません。
無断コピーの抑止は、技術ではなく [使用許諾契約書](../../../taskdeck/legal/EULA.md) で扱います。

## 2. 拡張パッケージ

**守ること: 署名のないコードを実行しないこと。**

- パッケージは `{manifest, code}` を並び順を固定した JSON にして署名します。
- アプリは**読み込むときと、起動のたび**に署名を確認します。保存後に書き換えられても検出します。
- `manifest` も署名の対象です。`trialLimit` だけ書き換える、といった改造も弾かれます。

**守らないこと: 拡張のコードをサンドボックスに閉じ込めること。**

拡張は `new Function` でページと同じ文脈で動きます。その気になれば
`document` や `localStorage` に直接触れます。これを承知のうえで、次のように判断しました。

- 実行できるのは**販売元が署名したコードだけ**なので、信頼の起点は署名にある
- iframe や Worker で隔離すると、画面を本体と同じ見た目で描けなくなる（本体の CSS を共有できない）
- 隔離しても、拡張に画面を描かせる以上は完全には防げない

将来、**第三者が作った拡張を売る場**（パッケージの市場）を作るなら、この判断は見直しが必要です。
そのときは「署名する前に販売者がコードを読む」運用か、Worker + メッセージ受け渡しへの作り替えを検討します。
判断の記録は [ADR-0003](ADR/0003-拡張を署名つきパッケージにする.md) にあります。

## 3. 利用者のデータ

- データは localStorage のみ。外部へは送信しません。
- 表示するときは、利用者が入力した文字を必ず `escapeHtml()` で無害化しています（タスク名にタグを書いても実行されません）。
- 読み込む JSON は `normalize()` を通し、想定外の形を捨てます。

**注意すべき点:**

- localStorage は暗号化されません。端末を共有している場合、他の利用者から読める可能性があります。
- ブラウザのデータ削除で消えます。バックアップは利用者の責任である旨を、マニュアルと使用許諾契約書に書いています。
- 拡張のデータは本体の JSON バックアップに含まれません（拡張ごとに書き出しが必要）。

## 4. 販売者の秘密鍵

**製品全体で、いちばん失ってはいけないもの。**

- `keys/private.json` に置き、`.gitignore` で Git から除外しています。
- `build.sh` は、配布物に `private_key` の文字列が混ざっていないかを毎回確かめます。CI でも同じ確認をします。
- 失うと新しいキー・新しい拡張を発行できません。作り直すと**発行済みのキーがすべて無効**になります。
- 漏れると第三者がキーを作れます。その場合は鍵を作り直し、購入者全員にキーを再発行することになります。

保管は、パスワード管理ソフトか暗号化した外部メディアへ。リポジトリの外に置きます。

## 5. 依存関係

外部ライブラリを 1 つも使っていません（署名の検証も自前実装）。
そのため、依存パッケージの乗っ取りによる混入経路がありません。
代わりに、暗号の実装が自前である責任を負います。実装は
Python 側と JavaScript 側の突き合わせテストで検証しています
（`tests/test_license.py`、`tests/test_package.py`）。
