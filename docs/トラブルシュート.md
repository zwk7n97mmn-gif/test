# トラブルシュート

📍`🏠ホーム > 📁Giteaイシュー自動返信キット > トラブルシュート`

---


## 返信が始まらない

`help-AI` ラベルが付いているか確認します。付いているのに始まらない場合は、一度外して付け直します。

それでも始まらないときは、実行ログの「起動条件の判定」を見ます。判定の理由が出ています。

```
action=labeled is_pr=0 has_label=1 added=[進捗/未着手 ] run=false reason=今回付与されたのは help-AI 以外のラベル
```

`help-AI` が付いたままで別のラベルを足した場合は、**意図的に起動しません**（二重返信を防ぐため）。
一度 `help-AI` を外して付け直してください。

## 「調査中」のまま止まっている

返信の生成中か、生成に失敗しています。失敗した場合はコメントが失敗の旨に書き換わります。
書き換わらないまま止まっているときは、ジョブがタイムアウト（既定 90 分）で打ち切られた可能性があります。

## 返信は出たが「資料が見つからない」と言っている

参照リポジトリの取得に失敗している可能性があります。実行ログの「参照リポジトリを取得」を見ます。

```
ok      src (org/app)
MISSING wiki (org/app.wiki)
::warning::参照リポジトリの取得に失敗しました: wiki（...）
```

`MISSING` が出ていたら、次の順に確認します。

1. **リポジトリが改名・削除されていないか。** Gitea は旧名への API 要求を 301 で新名へ転送しますが、
   **git の clone はリダイレクトを追いません。** 旧名を指したままだと `Not found` になり、
   権限不足とまったく同じ文言が出ます
2. **bot が対象リポジトリを読めるか**（private なら read 以上のコラボレータ権限が要ります）
3. `refs.json` の `ref`（ブランチ名）が実在するか。`master` のリポジトリを `main` で取ろうとしていないか

## 「Claude Code CLI に想定したフラグがありません」で止まる

CLI の版が変わり、フラグ名が変わっています。ランナー上で `claude --help` を実行して確認し、
`scripts/run_claude.sh` の `FLAGS` と `ARGS` を合わせてください。

版を固定したい場合は、ワークフローの `CLAUDE_CLI_VERSION` にバージョンを入れます。

## 「契約プランの利用上限に達した」と出た

契約プランの枠を使い切っています。**追加の請求は発生していません。**
コメントに書かれたリセット時刻を過ぎてから、`help-AI` ラベルを付け直してください。

頻繁に当たる場合は、1 回あたりの消費を減らせます。

- 質問の範囲を具体的に書く（対象の機能・ファイル名を明示する）
- `MAX_TURNS` を下げる
- `refs.json` から不要な参照先を外す。`sparse` で読めない形式（Excel・Word 等）を落とす

## 「ANTHROPIC_API_KEY と CLAUDE_CODE_OAUTH_TOKEN の両方が設定されています」で止まる

意図しない従量課金を防ぐための停止です。契約プランの枠で動かすなら、
Secrets から `ANTHROPIC_API_KEY` を削除してください。
逆に従量課金で動かしたい場合は、`CLAUDE_CODE_OAUTH_TOKEN` を外し、
ワークフローの「返信を生成」ステップの `env` を差し替えてください。

## 返信が途中で切れている

出力の上限に達しています。次のいずれかで対処します。

- 質問の範囲を絞って聞き直す（いちばん確実）
- `MAX_TURNS` を下げて、調査より回答に token を回す
- CLI の版を上げる

環境変数で出力上限を上げようとする前に、**その変数に許容される値の範囲**を確認してください。
範囲外の値を設定すると、プロセスが起動する前に落ちて**返信が 1 件も出なくなります**。

## 同じイシューに返信が 2 件付いた

トリガーに `opened` を足していないか確認してください。イシュー作成時、Gitea は `opened` と
`labeled` の両方を発火するため、両方を拾うと 2 つのジョブが起動します。
`concurrency` の `group` にイシュー番号が入っているかも確認します。

## 返信に文字化けが混じる

長い返信で起きやすい事象です。**特に注意すべきなのは、SQL やコードブロックの中で化けた場合**で、
そのままコピーすると壊れた文字列がデータに入ります。返信のコードを使う前に、
置換文字（`�`）が含まれていないか確認してください。

本文中で化けた場合は文脈から読み替えられます。追加質問で再生成するのも手です。

## 手元で切り分ける

通信せずに、部品ごとに確かめられます。

```bash
# 起動条件の判定
GITHUB_EVENT_PATH=event.json bash scripts/gate.sh

# プロンプトに何が渡っているか
EVENT_PATH=event.json COMMENTS_FILE=comments.json BOT_LOGIN=ai-bot bash scripts/build_prompt.sh

# API 呼び出しの中身（送信しない）
DRY_RUN=1 GITEA_API=https://gitea.example.com/api/v1/repos/org/repo \
  bash scripts/gitea_api.sh update-comment 123 reply.md

# CLI に渡す引数（実行しない）
DRY_RUN=1 PROMPT_FILE=prompt.txt bash scripts/run_claude.sh

# 全テスト
bash tests/run_all.sh
```
