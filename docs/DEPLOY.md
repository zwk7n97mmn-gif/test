# スマートフォンで実行する手順

## 前提：HTTPS が必須

このツールが使う機能の大半は、ブラウザの **セキュアコンテキスト（HTTPS または localhost）** でのみ有効になります。
`http://192.168.x.x:8080` のように **IP アドレスへ直接アクセスすると機能が落ちます**。

実測した差は次のとおりです（Chromium で計測）。

| 機能 | HTTPS / localhost | http://（IP 直アクセス） |
|---|---|---|
| `isSecureContext` | ✅ true | ❌ false |
| Service Worker（ホーム画面追加・オフライン） | ✅ | ❌ 利用不可 |
| OPFS（素材の保存・復帰） | ✅ | ❌ 利用不可 |
| Screen Wake Lock（画面消灯の抑止） | ✅ | ❌ 利用不可 |
| **WebCodecs（高速・中断に強い書き出し）** | ✅ | ❌ 利用不可 |
| MediaRecorder（実時間の書き出し） | ✅ | ✅ |
| 選択される書き出し方式 | `webcodecs`（高速） | `mediarecorder`（**実時間**） |

> HTTP でもアプリは起動し、編集・字幕・サムネイル・キャプションは動きます（エラーも出ません）。
> ただし書き出しが実時間方式へ退避し、画面ロックで壊れるリスクが戻ります。
> **スマートフォンで使うなら HTTPS で配信してください。**

## 方法 A：GitHub Pages で公開する（推奨）

追加のツールが不要で、HTTPS が自動で付きます。サブパス配信（`/<リポジトリ名>/`）で
動作することは検証済みです（manifest・Service Worker のスコープ・オフライン起動を確認）。

1. GitHub でリポジトリを開く
2. **Settings** → 左メニューの **Pages**
3. *Build and deployment* の **Source** を `Deploy from a branch` にする
4. **Branch** に `claude/video-editor-tool-45o42o`、フォルダは `/ (root)` を選んで **Save**
5. 1〜2 分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` が発行される
6. その URL をスマートフォンで開く

> リポジトリが Private の場合、GitHub Pages の公開には有料プランが必要です。
> Public にできない場合は方法 B か C を使ってください。

### 公開後の確認

- ページが開き、下部にタブ列が出る
- 「書き出し」タブの **出力形式** に `（高速・再生に依存しない）` と表示される
  → ここが `（実時間）` なら WebCodecs が使えていません（後述の対処へ）

## 方法 B：Cloudflare Pages / Netlify にドラッグ＆ドロップ

GitHub と連携せず、フォルダをそのまま置くだけで HTTPS 配信できます。

1. リポジトリを ZIP でダウンロードして展開（または `git clone`）
2. [Cloudflare Pages](https://pages.cloudflare.com/) または [Netlify Drop](https://app.netlify.com/drop) を開く
3. フォルダ全体をドラッグ＆ドロップ
4. 発行された HTTPS の URL をスマートフォンで開く

ビルド設定は不要です（ビルド工程がないため、出力ディレクトリはリポジトリのルート）。

---

## 方法 C：手元の PC を一時的に HTTPS 公開する（開発・動作確認向け）

PC で動かしているサーバへ、スマートフォンから HTTPS でつなぎます。
コードを書き換えながら実機で試すときに便利です。

```bash
# 1) PC でアプリを起動
npm start                      # http://localhost:8080

# 2) 別のターミナルでトンネルを張る（どちらか）
cloudflared tunnel --url http://localhost:8080
npx ngrok http 8080
```

表示された `https://....trycloudflare.com` などの URL をスマートフォンで開きます。
URL は起動のたびに変わり、PC を止めると使えなくなります。

## ホーム画面に追加してアプリのように使う

### iPhone / iPad（Safari）

1. **Safari** で URL を開く（Chrome など他のブラウザでは追加できません）
2. 下部の **共有ボタン**（□に↑）をタップ
3. **「ホーム画面に追加」** を選ぶ
4. 名前を確認して **「追加」**

ホーム画面のアイコンから起動すると、アドレスバーのない全画面で立ち上がります。

### Android（Chrome）

1. Chrome で URL を開く
2. 右上の **⋮** をタップ
3. **「アプリをインストール」** または **「ホーム画面に追加」**

## 初回に試す流れ

1. アイコンから起動する
2. 画面中央の枠をタップ → **写真アプリから動画を選ぶ**（30 秒〜2 分程度が試しやすい）
3. 解析が自動で走り、**「自動処理」** ダイアログが出る → **「実行する」**
4. **字幕**タブでテキストを入力（オフラインではタイムコードのみ自動生成されます）
5. **サムネ**タブ → 「候補を自動抽出」→ 気に入ったものを選ぶ
6. **投稿文**タブ → 「キャプションを生成」
7. **書き出し**タブ → 「動画を書き出す」→ 完了後 **「📤 共有 / 保存」** から SNS アプリへ

一度使ったあとはブラウザを閉じても、次に開いたときに**素材ごと**続きから再開できます。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 「ホーム画面に追加」が出ない | HTTPS で配信されていない／iOS で Safari 以外を使っている |
| 出力形式が「（実時間）」と出る | WebCodecs が使えない環境。iOS は 17 以降、Android Chrome は最新版へ更新。それでも出る場合はその端末では実時間方式で動きます（成果物は得られます） |
| 動画を選んでも「再生できません」 | 端末が対応しないコーデック。iPhone なら 設定 → カメラ → フォーマット を **「互換性優先」** にして撮り直すと H.264 になります |
| 解析の途中でページが再読み込みされる | メモリ不足。素材を短く分割するか、解像度を下げてください |
| 書き出しが途中で止まる | 画面ロックを抑止していますが、OS が強制的にタブを止めることがあります。書き出し中は他アプリへ切り替えないでください |
| 「素材を保存できませんでした」と出る | 端末の空き容量不足、または素材が 600MB 超。編集内容は保存されますが、復帰時に動画の選び直しが必要です |
| 前回の続きが復元されない | プライベートブラウジングでは保存されません。通常のタブで開いてください |

## セキュリティとプライバシー

- 動画・音声・画像は**端末内でのみ**処理され、サーバへ送信されません
- 例外は「外部 STT」を自分で設定した場合のみ（音声が設定先へ送られます）
- STT の API キーはメモリ上のみで保持し、保存しません
- 公開 URL は誰でもアクセスできます。**アプリを置くだけで、あなたの動画が他人に見えることはありません**が、
  URL を共有する範囲には注意してください
