# 運用

動き始めた後に開く資料です。初回のセットアップは [SETUP.md](SETUP.md) にあります。

## ふだんやること

**ありません。** 毎日 8:00 と 21:00（日本時間）に自動で投稿されます。

180 件を重複なしで一巡すると（**90 日分**）、順序を変えて次の巡回に入ります。
コンテンツを足さなくても止まりません。

---

## 手動で動かす

Actions タブ → 「定期投稿」→ **Run workflow**

| 入力 | 効果 |
|---|---|
| `dry_run` にチェック | 投稿せず、次に出る文面をログに出すだけ |
| `only` に `bluesky` / `x` | 片方だけに投稿する |
| 両方とも空のまま実行 | 通常どおり 1 件投稿し、状態を更新する |

手動実行しても巡回はそのまま進みます（1 件消費されます）。

## 手元で動かす

認証情報なしで動くものが 3 つあります。

```bash
python src/post.py --dry-run       # 次に投稿される内容を表示
python tests/validate.py --report  # 全件の検証と文字数一覧
python tests/test_logic.py         # ロジックのテスト
```

## 失敗したときの見方

ワークフローが失敗すると、GitHub からリポジトリ所有者にメールが届きます
（Settings → Notifications で調整可能）。

Actions タブ → 失敗した実行 → 「投稿する」ステップのログを開くと、
どちらのプラットフォームで何が起きたかが日本語で出ています。

**失敗しても、その回の豆知識は消費されません。** 次回に持ち越されます。
ただし片方だけ成功していた場合は消費されます（もう一度出すと重複するため）。

### よくある失敗

| ログに出るもの | 原因と対処 |
|---|---|
| `X: 投稿失敗 — HTTP 403` | アクセストークンの権限不足。App permissions を Read and write にした**後で**トークンを再発行する（[SETUP.md](SETUP.md) 2-3） |
| `X: レート制限のため今回は見送り` | 無料枠の月 500 投稿に到達。異常ではない。Bluesky には投稿済みで、ワークフローは成功扱い |
| `Bluesky: 投稿失敗 — HTTP 401` | アプリパスワードが失効・変更されている。再発行して Secrets を更新する |
| `投稿先が 1 つも設定されていません` | Secrets が未設定か名前が違う。[SETUP.md](SETUP.md) の表と綴りを見比べる |
| `コンテンツの検証に失敗したため投稿を中止します` | 追加した豆知識が文字数超過などで壊れている。`python tests/validate.py --report` で該当箇所が出る |
| `投稿履歴の push に失敗しました` | 状態のコミットが競合した。3 回まで自動再試行済み。次回の実行で自然に解消する |

### 実行時刻は正確ではありません

GitHub Actions の定期実行は、混雑時に数分〜数十分遅れることがあります。
「毎日きっかり 8:00」ではなく「毎朝 8 時台」くらいに考えてください。
これは GitHub 側の仕様で、こちら側では制御できません。

## 設定を変える

### 投稿時刻を変えたい

`.github/workflows/post.yml` の `cron` を編集します。**UTC 指定**なので、
日本時間から 9 時間引いてください（例: 7:00 JST → `0 22 * * *`）。

### 豆知識を追加したい

`content/tips/` の JSON に追記して PR を出すと、CI が文字数・出典・重複を
自動で検証します。基準は [EDITORIAL.md](EDITORIAL.md)。

### 止めたい / 再開したい

Actions タブ → 「定期投稿」→ 右上の `...` → **Disable workflow**。
再開は同じ場所から Enable します。状態はそのまま残るので、続きから再開されます。

### 鍵を漏らしてしまったら

- Bluesky: 設定からそのアプリパスワードを削除して再発行
- X: Developer Portal で Regenerate

いずれも GitHub Secrets の値を新しいものに差し替えれば復旧します。
**古い鍵を失効させるのが先**で、Secrets の更新は後で構いません。

## 投稿履歴を直す

`state/posted.json` が投稿履歴です。手で編集して構いません。

| やりたいこと | 変更 |
|---|---|
| 最初からやり直す | `{"cycle": 1, "done_ids": [], "last_category": "", "history": []}` に戻す |
| 次の巡回に進める | `cycle` を 1 増やし、`done_ids` を `[]` にする |
| 特定の 1 件をもう一度出す | `done_ids` からその id を消す |

出題順は巡回番号から決定的に決まるので（[ARCHITECTURE.md](ARCHITECTURE.md)）、
このファイルが壊れても、消えても、同じ順序を再現できます。
ファイルが読めない場合は初期値で続行し、投稿は止まりません。
