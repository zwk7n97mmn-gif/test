# リリース手順

## 版の付けかた

`メジャー.マイナー.修正`（例 `1.2.0`）。

| 上げる桁 | どんなとき |
|---|---|
| メジャー | 保存データの形が変わり、古い版で読めなくなるとき |
| マイナー | 機能を足したとき、拡張 API に項目を足したとき |
| 修正 | 不具合を直したとき |

拡張は本体とは別に版を持ちます。本体 1.2.0 と 確定申告 1.0.1 が同居して構いません。

## 出す手順

```bash
# 1. テストを通す
python3 taskdeck/tests/test_license.py
python3 taskdeck/tests/test_package.py
node taskdeck/tests/ui_smoke.mjs
node taskdeck/tests/ui_extension.mjs

# 2. 版を書き換える
#    - 拡張なら extensions/<id>/manifest.json の version

# 3. 配布物を作る（本体と拡張がまとめて出ます）
VERSION=1.2.0 bash taskdeck/tools/build.sh

# 4. 中身を確かめる
unzip -l taskdeck/dist/taskdeck-1.2.0.zip

# 5. 展開して、実際に開いて動かす
```

`build.sh` は、公開鍵が入っていないとき・テストが落ちたとき・
配布物に秘密鍵らしき文字列が混ざったときは、ZIP を作らずに止まります。

## 出したあと

1. ダウンロード先（サーバー、S3、決済サービス）へ ZIP を置く
2. 販売ページの版表記を直す
3. 購入者へ案内する（`docs/MAIL-TEMPLATES.md` の「更新版のお知らせ」）
4. このドキュメント群の「対象バージョン」を直す

## 拡張だけを出し直すとき

```bash
python3 taskdeck/tools/pkg.py build taskdeck/extensions/tax
python3 taskdeck/tools/pkg.py verify taskdeck/dist/tax-1.0.1.tdpkg
```

購入者は新しい `.tdpkg` を読み込むだけです。**ライセンスキーの再発行は要りません**
（権利名が同じであれば）。保存済みのデータもそのまま残ります。

## 絶対に変えてはいけないもの

- **公開鍵。** 変えると、発行済みのキーと配布済みの拡張がすべて無効になります
- **拡張の `id`。** 保存領域の名前になっているため、変えると利用者のデータが行方不明になります
- **localStorage のキー名。** 上げるのは、古い形を意図的に切り捨てるときだけです

## 秘密鍵の引き継ぎ

事業を続ける限り必要になります。次の 2 つを、リポジトリの外で確実に引き継いでください。

1. `keys/private.json`（秘密鍵）
2. `keys/issued.csv`（発行の控え。誰に何を売ったかの記録）
