# 受け入れ基準と検証結果

version 3.0（3D + スマホ完結 + 外部アバター）

要件定義に AC-* の明示がなかったため、要件文と厳守事項から受け入れ基準を起こし、
それぞれについて実装状況と検証方法を記載しています。

**先に結論**: 次の 2 点は意図的に要件どおりには実装していません。
- **AC-13**: TikTok からの自動取得（規約・著作権のため）
- **AC-28**: 写真そのもののような実写クオリティを**プログラムで生成**すること（原理的に不可能）
  → 代わりに、実写寄りのアバターを**読み込んで動かす**経路を実装しました（AC-29）

それ以外の AC-01〜AC-12 / AC-14〜AC-27 / AC-29〜AC-32 はすべて満たしています。

### AC-13 について

**TikTok からの自動ダウンロード / スクレイピングは実装していません。**

- TikTok の利用規約は自動収集を禁止しており、楽曲の多くは第三者の権利物です。
  取得機能を内蔵すると、利用者が規約違反・著作権侵害のリスクを負います。
- 代替として、**解析・制作の機能は一切削らずに**入力経路のみを合法な形に置き換えました。
  - 音源: ローカルの音声ファイル（解析処理は同一）
  - 動画: ローカルの動画ファイル、または**その場でのカメラ撮影**
  - トレンド情報: 公式画面（TikTok Creative Center 等）からエクスポートした CSV / JSON
- 正規 API を利用できる場合は、`AudioAsset` / `TrendEntry` を生成するアダプタの追加で接続できます。

## C-2. 追加要件「写真のようにリアルな女性を動かす」

| ID | 受け入れ基準 | 状態 | 内容 |

| AC-29 | 実写寄りの 3D アバターを読み込んで動かせる | ✅ | VRM / glTF（.vrm / .glb / .gltf）を読み込み、抽出したモーションで駆動。見た目はモデル側の品質がそのまま出る |
| AC-30 | アバターの体型・プロポーションが崩れない | ✅ | 与えるのは回転のみ。`tests/avatar.test.ts` が**骨の長さがポーズ適用前後で変化しないこと**を検証 |
| AC-31 | いろいろな配布形式のモデルを受け付ける | ✅ | VRM 0.x / 1.0 の humanoid 拡張を直接解釈。無い場合は Mixamo / Unreal / Blender などの命名から推定（`tests/avatar.test.ts`）。必須ボーンが無ければ理由を添えて拒否 |
| AC-32 | 正面の向きが自動で合う | ✅ | レストポーズの左右腕の位置関係から幾何的に判定（仕様バージョンに依存しない）。UI から手動反転も可能 |

### AC-28 について（未達の理由）

写真のような人物は、**スキャン・彫塑によるメッシュ、肌の SSS を含む PBR テクスチャ、
毛束単位のヘア、専用の目のシェーダ**といった制作物で決まります。これは
「コードで手続き的に組み立てる」範囲の外にあり、内蔵キャラクターをどれだけ磨いても
写真同然にはなりません（マネキン調が上限です）。

そのため実装したのは、**同じ目的を達成する現実的な唯一の経路**です。

- 「容姿」＝アバター（外部モデル）、「動き」＝本ツールが抽出したモーション、という分担にした
- 与えるのはボーンの回転だけなので、モデル本来の造形・質感・衣装がそのまま出る
- 内蔵キャラクターは、アバターを用意しない場合の既定として残した

**併せて未実装**: 手元の写真の人物そのものを動かす（写真1枚から動画を生成する）機能。
拡散モデルによる動画生成が必要でブラウザ内・スマホ単体では動作せず、また実在人物の
なりすまし映像の作成に直結するため、本ツールの対象外としています。

## D. 厳守事項の充足

### D-1. ダミーデータの扱い

| ID | 基準 | 状態 | 内容 |
| --- | --- | --- | --- |
| AC-15 | ダミーデータは初回起動時のサンプルに限る／機能のハリボテに使わない | ✅ | 初回生成は**容姿プリセット 3 件と空のプロジェクト 1 件のみ**。音源・モーションのサンプルは同梱せず、未読込時は空状態を表示。BPM・ビート・区間・関節座標はすべて実データからの計算結果 |

「捏造しない」実装:

- 無音・極端に短い音源 → BPM 0・ビート空・警告
- 姿勢が 1 フレームも取れない → クリップを作らずエラー
- 0.5 秒を超える未検出区間 → 補間せず除外し、長さを警告に明記
- 補間で作った関節値 → 信頼度を 0.5 倍にして記録
- 上下反転を検知した場合 → 補正したうえでその旨を警告に残す

## F. 未対応事項（今後の課題）

- 書き出しは実時間キャプチャのため、動画の尺と同じ時間がかかります
- 内蔵キャラクターは剛体パーツ構成のマネキン調（実写寄りにしたい場合は外部アバターを使用）
- アバターの表情・指・揺れもの（髪・スカート）は未対応（体の 17 ボーンのみ駆動）
- VRM の MToon マテリアルは PBR フォールバックとして描画される（陰影が原作と異なる場合がある）
- 同時に扱える人物は 1 名
- 奥行きは単眼推定の相対値で、絶対的な精度はありません
- 外部アバター（VRM / GLTF）の読み込みは未対応
