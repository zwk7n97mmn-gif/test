### AC-13 について

要件は「TikTok で人気の音源を分析し、動きは元動画から撮ってくる」でしたが、
**TikTok からの自動ダウンロード / スクレイピングは実装していません。**

- TikTok の利用規約は自動収集を禁止しており、楽曲の多くは第三者の権利物です。
  取得機能をツールに内蔵すると、利用者が規約違反・著作権侵害のリスクを負います。
- 代替として、**解析・制作の機能は一切削らずに**、入力経路のみを合法な形に置き換えました。
  - 音源: ローカルの音声ファイルを読み込む（解析処理は同一）
  - 動画: ローカルの動画ファイルを読み込む（抽出処理は同一）
  - トレンド情報: 公式画面（TikTok Creative Center 等）からエクスポートした
    CSV / JSON を取り込む
- 正規 API を利用できる場合は、`AudioAsset` / `TrendEntry` を生成するアダプタを
  1 つ追加するだけで接続できる構造にしています。

「人気音源を分析して、その曲に合った動画を作る」という目的自体は、上記の経路で
完全に達成できます。

## B. 厳守事項の充足

### B-1. ダミーデータの扱い

| ID | 基準 | 状態 | 内容 |
| --- | --- | --- | --- |
| AC-15 | ダミーデータは初回起動時のサンプルに限る／機能のハリボテに使わない | ✅ | 初回起動時に生成するのは**キャラクター容姿プリセット 3 件と空のプロジェクト 1 件のみ**。音源・モーションのサンプルは同梱せず、未読込時は空状態を表示する。BPM・ビート・区間・関節座標はすべて実データからの計算結果で、推定できない場合は 0 と警告を返し、値を捏造しない |

具体的な「捏造しない」実装:

- 無音・極端に短い音源 → BPM 0・ビート空・警告（`analyze.ts`）
- 姿勢が 1 フレームも取れない → クリップを作らずエラー（`postProcessFrames`）
- 0.5 秒を超える未検出区間 → 補間せず除外し、長さを警告に明記
- 補間で作った関節値 → 信頼度を 0.5 倍にして記録

境界値の実装と検証:

| 種別 | 境界 | 挙動 |
| --- | --- | --- |
| 音源 | 長さ 0 / 無音 / FFT 2 フレーム未満 | 例外を出さず警告付きの空結果（テスト済み） |
| 音源 | 10 分超 | 先頭 10 分のみ解析し警告に明記 |
| 音源 | 60MB 超 | 読み込み前に拒否し、上限を表示 |
| 動画 | 300MB 超 / 60 秒超の区間 | 拒否し、対処方法を表示 |
| 動画 | 映像トラック無し / 長さ不明 / デコード不可 | 個別のエラーメッセージ |
| 姿勢 | 検出 0 件 / 検出率 60% 未満 / 信頼度 50% 未満 | エラーまたは警告 |
| 姿勢 | 胴が潰れたフレーム、関節が重なった退化姿勢 | フレーム棄却 / 既定方向へフォールバック（テスト済み） |
| 文字列 | プロジェクト名 120 字・キャラ名 60 字・テロップ 500 字 | 切り詰め（テスト済み）。テロップは自動折り返し最大 6 行 |
| 件数 | トレンド 5000 件 | 取り込み可能。表示は先頭 200 件＋総数表示（テスト済み） |
| 数値 | 範囲外・NaN・不正な色コード・未知の列挙値 | クランプまたは既定値へ（テスト済み） |
| 保存 | 容量超過 | `QuotaExceededError` を専用メッセージに変換、使用率 80% 超で警告 |
