# Motion Muse 設計書

version 1.0 / 2026-08-12

---

## 1. 背景と要件の解釈

### 1.1 元の要件

> 美少女の動画制作ツール。TikTok で人気の音源を分析し、そこから容姿だけを変えて
> 動きのモーションは元動画から撮ってきて制作できるもの。

### 1.2 分解した機能要件

| # | 要件 | 本設計での実現 |
| --- | --- | --- |
| R1 | 人気音源を分析する | 音声ファイルの BPM / ビート / 楽曲構成（サビ）を実測解析。トレンド一覧は公式エクスポート（CSV/JSON）の取り込みで管理 |
| R2 | 動きは元動画から取る | 動画に対し姿勢推定を実行し、関節座標列（モーションクリップ）として抽出 |
| R3 | 容姿だけを変える | 容姿パラメータと骨格リグを、モーションデータから完全に分離。骨の「向き」はモーション、「長さ」はリグが持つ |
| R4 | 動画として制作・出力する | 音源・モーション・容姿・演出を合成し、音声付き動画として書き出し |

### 1.3 要件を字義通りに実装しなかった点（重要）

**TikTok からの自動取得（スクレイピング / ダウンロード）は実装していません。**

- TikTok の利用規約は自動収集・ダウンロードを禁止しており、楽曲の多くは第三者が
  権利を持つ商用音源です。ツールにその機能を内蔵すると、利用者が規約違反・著作権侵害の
  リスクを負う構造になります。
- 代替として、**同じ成果物を作れる合法的な入力経路**を用意しました。
  - 音源: ユーザーがローカルの音声ファイルを読み込む（解析機能は完全に同一）
  - トレンド情報: TikTok Creative Center 等の公式画面からユーザーがエクスポートした
    CSV / JSON を取り込み、音源に紐づけて管理（`src/lib/trend/import.ts`）
  - 動画: ユーザーがローカルの動画ファイルを読み込む
- 将来、正規の API 経由で取得したい場合は、`AudioAsset` / `TrendEntry` を生成する
  アダプタを 1 つ追加するだけで差し替えられる構造にしています。

この点は本書 §9 および `docs/ACCEPTANCE.md` の AC-13 に明記しています。

## 2. 設計の中心となる考え方

### 2.1 「動き」と「容姿」の分離

要件の核心は「**動きは元動画のまま、容姿だけを変える**」ことです。これをデータ構造の
レベルで保証するため、次の 3 層に分離しています。

```
  元動画
    │  姿勢推定（MediaPipe Pose 33点）
    ▼
┌─────────────────────────────────────────────┐
│ MotionClip                                  │  ← 「動き」だけを持つ
│   ・腰を原点、胴長を 1 とする正規化座標      │     体格・画面内位置・解像度に非依存
│   ・関節ごとの信頼度                         │
│   ・root（画面内の移動量）は別フィールドに分離│
└─────────────────────────────────────────────┘
    │  retarget()  ← 「向き」だけを取り出す
    ▼
┌─────────────────────────────────────────────┐
│ CharacterRig（容姿から導出した骨の長さ）      │  ← 「容姿」だけを持つ
│   hipToSpine / upperArm / thigh / headRadius…│
└─────────────────────────────────────────────┘
    │  順運動学で再構成
    ▼
  PosedSkeleton → drawCharacter()
```

- `mapLandmarksToRig()` が **胴長 1 の正規化**を行うことで、元人物の体格情報を破棄します。
- `retarget()` は各骨の**方向ベクトルのみ**をモーションから取り、**長さはリグから**取ります。
- したがって、頭身・脚長・体型をどれだけ変えても、関節の角度＝振り付けは不変です。
  この不変性はテストで機械的に検証しています
  （`tests/pose.test.ts` の「容姿を変えても関節の角度は変わらない」）。

### 2.2 レンダリングは時刻の純関数

`renderFrame(ctx, time, input)` は内部に蓄積状態を持ちません。パーティクルは
ビート番号から決定的ハッシュで生成し、残像は過去時刻を再サンプリングして描きます。

- プレビューでシークした絵と、書き出した動画の絵が必ず一致する
- 任意の時刻から再開できる（書き出しの中断・再開が安全）

## 3. アーキテクチャ

### 3.1 全体構成

サーバーを持たない SPA です。素材・成果物はすべてブラウザ内（IndexedDB）に閉じ、
外部送信は一切ありません。

```
┌────────────── UI 層 (React) ──────────────┐
│ App / 5タブ / PreviewStage / Timeline      │
└──────────────┬─────────────────────────────┘
               │ WorkspaceProvider (状態 + 永続化)
┌──────────────▼─────────────────────────────┐
│ ドメイン層 (src/lib)                        │
│  audio/    解析 (FFT→オンセット→BPM→構成)   │
│  pose/     抽出・正規化・平滑化              │
│  character/容姿パラメータ・リグ・描画        │
│  render/   合成 (背景/演出/テロップ)         │
│  export/   MediaRecorder 書き出し           │
│  trend/    トレンド一覧の取り込み            │
│  storage/  IndexedDB                        │
└─────────────────────────────────────────────┘
```

## 4. 音源解析

`analyzeAudio(samples, sampleRate)` は次の順で処理します。すべて実データに対する
計算であり、推定できない場合は値を捏造せず `0` と警告を返します。

| 段階 | 手法 | 実装 |
| --- | --- | --- |
| 1. STFT | Hann窓 1024 / ホップ 512 | `FFT.magnitude` |
| 2. オンセット強度 | 対数圧縮スペクトルのスペクトルフラックス | `analyze.ts` |
| 3. オンセット検出 | 移動中央値による適応しきい値＋局所最大＋50ms のデバウンス | `pickOnsets` |
| 4. BPM 推定 | オンセット包絡の自己相関 × テンポ事前分布（log正規, 中心120BPM）＋放物線補間 | `estimateTempo` |
| 5. ビート追跡 | 動的計画法（Ellis 2007）。遷移コスト `-α·log²(Δ/period)` | `trackBeats` |
| 6. 小節頭推定 | 4拍周期の位相のうち、オンセット×低域が最大となる位相を選択 | `trackBeats` |
| 7. 楽曲構成 | ビート同期の対数バンド特徴 → 自己類似行列 → チェッカーボードカーネル（Foote 2000）でノベルティ → ピーク検出 | `segmentSections` |
| 8. サビ推定 | 区間エネルギー(0.65) + 他区間との平均類似度＝反復性(0.35) | `labelSections` |

### 4.1 検証結果

`tests/audio.test.ts` で合成クリック音源（90 / 120 / 128 / 140 BPM）に対し
**誤差 ±2 BPM 以内**で推定できることを確認しています。ビート間隔の平均が拍長と一致すること、
小節位置が 0→1→2→3 と循環すること、静→動の構成でサビが後半（高エネルギー側）に
置かれることも検証済みです。

### 4.2 境界値

| 入力 | 挙動 |
| --- | --- |
| 長さ 0 | 例外を投げず、空の解析結果と警告 |
| FFT 2 フレーム未満 | テンポ解析を行わず警告 |
| 無音（RMS < 1e-4） | BPM 0・ビート空・警告 |
| 10 分超 | 先頭 10 分のみ解析し、その旨を警告に明記 |
| サンプリングレート ≤ 0 | 例外（プログラミングエラーとして扱う） |

## 5. モーション抽出

### 5.1 パイプライン

1. `<video>` を 1/targetFps 秒ごとにシークし、`seeked` を待って canvas へ描画
   （`requestVideoFrameCallback` に頼らず、決定的にフレームを取得するため）
2. `PoseLandmarker.detectForVideo` で 33 点を推定（GPU→CPU 自動フォールバック）
3. `mapLandmarksToRig` で 19 関節・胴長 1 の正規化空間へ写像
4. `postProcessFrames` で欠落補間 → 1€ Filter で平滑化 → 品質指標を算出

### 5.2 正規化の詳細

- x 座標に `videoWidth / videoHeight` を掛け、単位を「画像高さ」にそろえる
  （横長動画で体が横に潰れるのを防ぐ）
- 原点 = 左右の腰の中点、スケール = 腰中点→肩中点の距離
- 胴長が 1e-4 未満（真横 or 検出破綻）のフレームは **null を返して捨てる**
- 画面内の位置は `root`、体の向きは `facing`（肩幅/胴長の比）として分離保存

### 5.3 欠落の扱い（捏造しない方針）

| 状況 | 挙動 |
| --- | --- |
| 0.5 秒以内の欠落 | 前後フレームから線形補間。信頼度は 0.5 倍に落として記録 |
| 0.5 秒超の欠落 | 補間せず該当フレームを除外し、`quality.warnings` に長さを明記 |
| 全フレーム未検出 | クリップを作らずエラー。対処方法（全身が映る素材）を提示 |
| 検出率 < 60% / 平均信頼度 < 50% | クリップは作るが警告を UI に表示 |

### 5.4 制限

- 1 回の抽出は **60 秒まで**（`MAX_CLIP_SECONDS`）。それ以上は区間を分けて取り込みます。
- 同時に扱う人物は 1 名（`numPoses: 1`）。
- 2D の関節座標のみを扱い、奥行き（Z）は使用しません。前後関係は `mirrored` から
  推定した簡易的な重なり順で表現します。

## 6. キャラクター描画

### 6.1 容姿パラメータ

`CharacterAppearance` は 20 項目（髪型5・目3・衣装4・アクセ4・体型3・8色・頭身・脚長・線幅・頬）。
すべて `sanitizeAppearance()` を通り、範囲外の数値はクランプ、不正な色・列挙値は既定値に落ちます。

### 6.2 描画順とレイヤ

後ろ髪 → 奥側の脚 → 奥側の腕 → 手前の脚 → 下衣（スカート/ショーツ）→ 胴 →
手前の腕 → 首 → 頭（輪郭・目・眉・口・頬・前髪・アクセサリ）

奥側は `shade(color, -0.16)` で暗くし、簡易的な奥行きを与えます。

### 6.3 手足の描画方式（実装上の要点）

関節ごとに独立したカプセルを `fill` + `stroke` すると、**内側の丸キャップの輪郭が
関節に黒い円として残る**問題が発生します（開発中に実ブラウザで確認）。

これを避けるため、手足は折れ線を **同じパスに対する 2 回のストローク**で描いています。

```
太い線（幅 = 2*w + 2*outline, 輪郭色） → 細い線（幅 = 2*w, 塗り色）
lineCap / lineJoin = 'round'
```

こうすると丸い継ぎ目が自動生成され、内部に線が残りません。袖・靴は本体を描いた後に
重ねることで、袖口・靴の縁が意図した位置にだけ現れます。

### 6.4 二次モーション

髪とスカートの揺れは、直前フレームとのルート/頭部の水平速度から `sway` を算出して
制御点をずらすことで表現します。瞬きは時刻の関数（3.1 秒周期）とし、再現性を保っています。

## 7. 合成と同期

### 7.1 時間マッピング

`motionTimeAt(t)` が楽曲時刻からクリップ内時刻を求めます。

| モード | 計算 |
| --- | --- |
| `sync`（既定） | `経過拍 = (t - 最初の小節頭)/拍長 + オフセット拍` を `loopBeats` で剰余し、クリップ長へ線形写像。**振り付けを N 拍にぴったり収める**（例: 8 拍ループ） |
| `original` | クリップ本来の速度で再生し、クリップ長で剰余 |
| BPM 未検出時 | `sync` を選んでいても自動的に `original` 相当に退避（UI にもその旨を表示） |

### 7.2 演出

| 演出 | 駆動源 |
| --- | --- |
| ズームパンチ | ビート強度（直近ビートからの指数減衰、小節頭は 1.0 / それ以外 0.72 倍） |
| 背景の明滅 | 同上 |
| パーティクル | ビート番号 + 粒子番号の決定的ハッシュ（シークしても同じ絵） |
| 低音の波紋 | 低域バンドのエネルギー包絡 |
| 残像 | 0.07 秒 / 0.14 秒前の姿勢を再サンプリングして半透明描画 |

演出はあくまで映像効果であり、**関節の角度＝モーションには一切干渉しません**。

### 7.3 テロップ

日本語には単語区切りが無いため、`wrapText()` は 1 文字ずつ実測幅で折り返します。
最大 6 行。文字色と縁取り色のコントラスト比を UI で計算し、4.5:1 未満なら警告を出し、
ワンクリックで読みやすい配色（白文字 / 黒縁）に戻せます。

## 8. 書き出し

`canvas.captureStream(fps)` に `MediaStreamAudioDestinationNode` の音声トラックを
足して `MediaRecorder` で録画します。

- **コーデック選択**: MP4(H.264/AAC) → WebM(VP9/Opus) → WebM(VP8) → WebM の順に
  `isTypeSupported` で判定。決まらなければ書き出しボタンを無効化し理由を表示。
- **トレードオフ**: MediaRecorder は実時間キャプチャのため、30 秒の動画には 30 秒かかります。
  代わりに音ズレが構造的に発生せず、追加ライブラリも不要です。オフライン高速書き出しには
  WebCodecs + マルチプレクサが必要で、本バージョンでは採用していません（§10）。
- **失敗時**: 空ファイルになった場合（タブ非表示など）は原因と対処を明示してエラーにします。

## 9. データと権利の扱い

- 音源・動画・モーション・プロジェクトはすべて IndexedDB に保存され、外部へ送信しません。
- モーションクリップに保存されるのは**関節座標と信頼度のみ**で、元動画のフレームや
  人物の外見情報は一切含まれません（`.motion.json` を開けば確認できます）。
- 「音源」「モーション」両タブに、外部サービスから自動取得しないこと、および
  素材の権利確認が必要であることを常時表示しています。
- 保存容量は `navigator.storage.estimate()` で監視し、80% 超で警告します。

## 12. アクセシビリティ方針

- 配色は全ペアのコントラスト比をテストで機械検証（本文 4.5:1 / 非テキスト 3:1）
- タブは WAI-ARIA Tabs パターン（`←` `→` `Home` `End`、`tabIndex` のロービング）
- 全フォーム部品は `label` と `aria-describedby` で説明・エラーに結び付け
- 進捗は `role="progressbar"` + `aria-valuenow`、通知は `role="alert"` / `role="status"`
- 波形タイムラインは装飾（`aria-hidden`）とし、操作は隣接する range 入力が担当
- スキップリンク、`:focus-visible` の 3px リング、`prefers-reduced-motion` 対応
