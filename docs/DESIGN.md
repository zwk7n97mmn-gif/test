# Motion Muse 設計書

version 2.0 / 2026-08-13
（v1.0 の 2D アニメ調から **3D ヒューマノイド + スマホ完結** へ全面改訂）

---

## 1. 要件と解釈

### 1.1 要件

> 美少女の動画制作ツール。TikTok で人気の音源を分析し、そこから容姿だけを変えて
> 動きのモーションは元動画から撮ってきて制作できるもの。
>
> 追加要件: **3次元の人間っぽい感じで**作ること。**スマホのみで完結する**ツールにすること。

### 1.2 分解

| # | 要件 | 実現方法 |
| --- | --- | --- |
| R1 | 人気音源を分析する | 音声ファイルの BPM / ビート / 楽曲構成（サビ）を実測解析。トレンド一覧は公式エクスポート（CSV/JSON）の取り込み |
| R2 | 動きは元動画から取る | 姿勢推定の **3D ワールドランドマーク**を関節座標列として抽出 |
| R3 | 容姿だけを変える | 容姿パラメータと骨格リグを、モーションデータから完全に分離 |
| R4 | **3次元の人間っぽく** | three.js による立体ヒューマノイド。実人体に近い比率・3灯ライティング・影 |
| R5 | **スマホのみで完結** | PWA（オフライン動作／ホーム画面追加）、カメラ撮影、縦1カラムUI、共有シート出力 |
| R6 | 動画として出力する | 音声付き動画として書き出し |

### 1.3 要件を字義通りに実装しなかった点

**TikTok からの自動取得（スクレイピング / ダウンロード）は実装していません。**
理由と代替手段は `docs/ACCEPTANCE.md` の AC-13 を参照してください（v1.0 から変更なし）。

## 2. 設計の中心となる考え方

### 2.1 「動き」と「容姿」の分離

```
  元動画 / カメラ撮影
    │  MediaPipe Pose → worldLandmarks（3D, メートル, 腰原点）
    ▼
┌──────────────────────────────────────────────────┐
│ MotionClip（formatVersion 2 = 3D）                │  ← 「動き」だけ
│   ・腰を原点、胴長を 1、Y上・Z手前の右手系        │     体格・立ち位置・カメラ距離に非依存
│   ・関節ごとの信頼度／root（画面内の立ち位置）    │
└──────────────────────────────────────────────────┘
    │  retarget()  ← 骨の「向き」だけを取り出す
    ▼
┌──────────────────────────────────────────────────┐
│ CharacterRig（容姿から導出した骨の長さ）           │  ← 「容姿」だけ
│   thigh / upperArm / headRadius / torsoRadius …   │
└──────────────────────────────────────────────────┘
    │  順運動学（3D）
    ▼
  PosedSkeleton → Humanoid.update() → three.js シーン
```

- `mapLandmarksToRig()` が胴長 1 で正規化し、体格の絶対サイズを破棄します。
- `retarget()` は各骨の**方向ベクトル（3D）だけ**をモーションから取り、**長さはリグから**取ります。
- したがって頭身・脚長・肩幅・体型をどれだけ変えても、関節の角度＝振り付けは不変です。
  これはテストで機械的に検証しています（`tests/pose.test.ts`）。

### 2.2 レンダリングは時刻の純関数

`renderFrame(ctx, time, input)` は内部に蓄積状態を持ちません。パーティクルはビート番号からの
決定的ハッシュで配置し、カメラ・ライトもすべて時刻から計算します。
そのためプレビューでシークした絵と、書き出した動画の絵が必ず一致します。

## 3. アーキテクチャ

サーバーを持たない SPA / PWA です。素材・成果物はすべてブラウザ内（IndexedDB）に閉じ、
外部送信は一切ありません。

```
┌──────────── UI 層 (React, 縦1カラム) ────────────┐
│ App / 下部ナビ5タブ / PreviewStage / Timeline     │
└──────────────┬────────────────────────────────────┘
               │ WorkspaceProvider（状態 + 永続化 + 描画ロック）
┌──────────────▼────────────────────────────────────┐
│ ドメイン層 (src/lib)                               │
│  audio/     解析 (FFT→オンセット→BPM→構成)         │
│  pose/      3D抽出・正規化・平滑化                  │
│  character/ 容姿パラメータ・リグ・three.jsメッシュ  │
│  render/    3Dステージ + 2Dオーバーレイ合成         │
│  export/    MediaRecorder 書き出し                 │
│  trend/     トレンド一覧の取り込み                  │
│  storage/   IndexedDB                              │
└────────────────────────────────────────────────────┘
```

主要ファイル:

## 4. 音源解析

`analyzeAudio(samples, sampleRate)` の処理はすべて実データに対する計算で、推定できない場合は
値を捏造せず 0 と警告を返します。

| 段階 | 手法 |
| --- | --- |
| 1. STFT | Hann窓 1024 / ホップ 512 |
| 2. オンセット強度 | 対数圧縮スペクトルのスペクトルフラックス |
| 3. オンセット検出 | 移動中央値による適応しきい値＋局所最大＋50ms デバウンス |
| 4. BPM 推定 | 自己相関 × テンポ事前分布（log正規, 中心120BPM）＋放物線補間 |
| 5. ビート追跡 | 動的計画法（Ellis 2007）、遷移コスト `-α·log²(Δ/period)` |
| 6. 小節頭推定 | 4拍周期の位相のうちオンセット×低域が最大のもの |
| 7. 楽曲構成 | ビート同期特徴の自己類似行列＋チェッカーボードカーネル（Foote 2000） |
| 8. サビ推定 | 区間エネルギー(0.65) + 反復性(0.35) |

合成クリック音源（90/120/128/140 BPM）で **誤差 ±2 BPM 以内**を検証済み。
境界値（長さ0・無音・極小・10分超・不正サンプルレート）もテスト済みです。

## 5. モーション抽出（3D）

### 5.1 パイプライン

1. `<video>` を 1/targetFps 秒ごとにシークし、`seeked` を待って canvas へ描画
2. **長辺 480px に縮小**してから `PoseLandmarker.detectForVideo`（スマホの処理時間対策）
3. `result.worldLandmarks`（メートル単位の 3D）を 19 関節・胴長 1 の空間へ写像
4. 欠落補間 → 1€ Filter → 上下反転の検査と補正 → 品質指標

### 5.2 座標系

MediaPipe のワールドランドマークは Y 下向き・Z がカメラ奥方向です。これを
**Y 上・Z 手前の右手系**へ変換し、原点を腰、単位を胴長にそろえます。

画面内の立ち位置は world 側では常に原点になるため、**画面座標のランドマークから
別途 `root` として算出**して分離保存します（キャラクターの左右移動に使用）。

### 5.3 欠落の扱い（捏造しない方針）

| 状況 | 挙動 |
| --- | --- |
| 0.5 秒以内の欠落 | 前後から線形補間。信頼度は 0.5 倍にして記録 |
| 0.5 秒超の欠落 | 補間せず除外し、`quality.warnings` に長さを明記 |
| 全フレーム未検出 | クリップを作らずエラー（対処方法を提示） |
| 上下反転 | 頭が腰より下のフレームが 8 割超なら Y を反転して補正し、警告 |
| 検出率 < 60% / 平均信頼度 < 50% | クリップは作るが警告を表示 |

### 5.4 制限

1 回の抽出は 60 秒まで、人物は 1 名。単眼推定のため奥行き（Z）は相対的な目安です。

## 6. 3D キャラクター

### 6.1 方針

**フォトリアルではなく「スタイライズド 3D ヒューマン（マネキン調）」**です。
スマートフォンで 30fps を維持することを優先し、スキニング（ボーン変形）を使わず、
**各パーツを独立した剛体として毎フレーム配置**しています。

- パーツ数 約 35、頂点数は数千程度
- 材質は `MeshStandardMaterial`（roughness 中心）
- キーライト（影付き）＋リムライト＋半球光の 3 灯
- 地面は `ShadowMaterial` で影だけを落とす

### 6.2 プロポーション

胴長（腰→胸）を 1 とする単位系で、既定値がおよそ **7 頭身**になるよう調整しています
（`tests/pose.test.ts` で 6〜8 頭身の範囲を検証）。

| 部位 | 長さ（胴長=1） |
| --- | --- |
| 腰→脊椎→胸 | 0.42 + 0.58 |
| 首→頭 | 0.30 ×頭スケール |
| 上腕 / 前腕 | 0.70 / 0.62 |
| 腿 / 脛 | 1.02 / 0.96 ×脚長 |

体型（スリム/ふつう/アスリート/グラマー）は胴・手足の太さ・肩幅・腰幅の係数として作用します。

### 6.3 実装上の要点

- **胴のひねり**: 骨の向き（+Y）だけでは体の正面が決まらないため、肩の軸（腰は腰の軸）を
  ヒントに基底を作り、`Matrix4.makeBasis(side, up, forward)` から姿勢を決めています。
  これにより肩が回ると胴も回ります。
- **顔のパーツは楕円体表面に置く**: 頭蓋メッシュの内側に置くと完全に埋没して見えなくなるため、
  頭蓋（楕円体）の表面 Z を解析的に計算して配置しています（開発中に実際に発生した不具合）。
- **虹彩・瞳孔は平面ディスク**: 球にすると白目の内部に埋まるため、白目表面のわずかに手前へ
  `CircleGeometry` を置いています。
- **衣装の Z ファイティング対策**: 衣装は体側と同じくびれ曲線を持たせず（pinch=0）、
  体より確実に外側を通る半径にしています。ウエストは下衣を上衣より外側に置いて重ねます。
- **色だけの変更ではジオメトリを作り直さない**: 骨格・髪型・衣装が同じならマテリアルの色だけ
  更新するため、スライダー操作中もフレーム落ちしません。

## 7. 合成と同期

### 7.1 時間マッピング

| モード | 計算 |
| --- | --- |
| `sync`（既定） | `経過拍 = (t - 最初の小節頭)/拍長 + オフセット拍` を `loopBeats` で剰余し、クリップ長へ線形写像 |
| `original` | クリップ本来の速度で再生し、クリップ長で剰余 |
| BPM 未検出時 | `sync` を選んでいても自動的に `original` 相当に退避（UI にも表示） |

### 7.2 演出（すべて 3D シーン側）

| 演出 | 駆動源 |
| --- | --- |
| ズームパンチ | ビート強度でカメラを前後に動かす |
| ライティング | キー/リムライトの強度をビートで変調 |
| パーティクル | `THREE.Points`。ビート番号からの決定的ハッシュで配置し、加算合成で減衰（黒＝不可視） |
| 床の発光 | 低域バンドのエネルギーで円形メッシュの不透明度と大きさを変調 |

テロップのみ 2D で重ねます（日本語の折り返しを 1 文字ずつ実測）。

### 7.3 WebGL コンテキストの共有

モバイルでは WebGL コンテキストの同時保持数が厳しいため、**アプリ全体で 1 つ**を共有します
（`getStage()`）。書き出し中はプレビュー描画を止める排他フラグ（`renderBusy`）を設けています。
`webglcontextlost` を監視し、失われた場合は画面に理由を出して復帰を待ちます。

## 8. スマホ完結のための設計

| 項目 | 実装 |
| --- | --- |
| **入力** | `<input type="file" accept="video/*" capture="environment">` で標準カメラを起動。`getUserMedia` より対応端末が広く、録画UIを自作しなくて済む |
| **レイアウト** | 縦1カラム固定。上部にプレビュー、下部に 5 タブのナビ。PC でも最大 560px で中央表示 |
| **タップ領域** | ボタン・入力とも最小 48px、スライダーのつまみは 28〜30px |
| **セーフエリア** | `viewport-fit=cover` + `env(safe-area-inset-*)` でノッチ／ホームインジケータを回避 |
| **iOS の自動ズーム対策** | 入力欄の font-size を 16px 以上に固定 |
| **音声** | iOS は無操作で `AudioContext` が起動しないため、再生ボタンのハンドラ内で `resume()` |
| **性能** | プレビューは縦 720px で描画し CSS 拡大／姿勢推定の入力は長辺 480px／既定の解析 fps は 20 |
| **初回ロード** | three.js・React を別チャンク化。MediaPipe（128KB）は抽出時に動的 import |
| **オフライン** | Service Worker。HTML はネットワーク優先、ハッシュ付きアセットとモデルはキャッシュ優先 |
| **インストール** | `manifest.webmanifest` + 自前生成アイコン。Android は `beforeinstallprompt`、iOS は手順を案内 |
| **出力** | Web Share API level 2 でファイルを共有シートへ。非対応時はダウンロードにフォールバック |

## 9. 書き出し

`canvas.captureStream(fps)` に `MediaStreamAudioDestinationNode` の音声トラックを足して
`MediaRecorder` で録画します。

- **コーデック選択**: MP4(H.264/AAC) → WebM(VP9/Opus) → WebM(VP8) → WebM の順に判定。
  iOS Safari では MP4 が選ばれ、そのまま SNS に渡せます。
- **トレードオフ**: 実時間キャプチャのため、30 秒の動画には 30 秒かかります。代わりに
  音ズレが構造的に発生せず、追加ライブラリも不要です。

## 10. データと権利の扱い

- すべて IndexedDB に保存され、外部へ送信しません。
- モーションクリップに保存されるのは**関節座標と信頼度のみ**で、元動画のフレームや
  人物の外見情報は一切含まれません（`.motion.json` を開けば確認できます）。
- 「音源」「モーション」両タブに、外部サービスから自動取得しないこと、および素材の
  権利確認が必要であることを常時表示しています。

## 13. アクセシビリティ方針

- 配色は全ペアのコントラスト比をテストで機械検証（本文 4.5:1 / 非テキスト 3:1）
- 下部ナビは WAI-ARIA Tabs パターン（`←` `→` `Home` `End`、ロービング `tabIndex`）
- 全フォーム部品は `label` と `aria-describedby` で説明・エラーに結び付け
- 進捗は `role="progressbar"` + `aria-valuenow`、通知は `role="alert"` / `role="status"`
- 波形タイムラインは装飾（`aria-hidden`）とし、操作は重ねた range 入力が担当
- スキップリンク、`:focus-visible` の 3px リング、`prefers-reduced-motion` 対応
- タップ領域は最小 48px（WCAG 2.2 Target Size (Minimum) の 24px を上回る）
