# テスト方針

サーバーが無く、購入者の手元で完結する製品です。
「出したあとで直す」ができないため、出す前に確かめる範囲を広めに取っています。

## 4 つのテスト

| テスト | 何を守るか | 実行 |
|---|---|---|
| `tests/test_license.py` | ライセンスキーの発行（Python）と検証（JavaScript）の一致 | `python3` |
| `tests/test_package.py` | 拡張パッケージの署名と検証の一致 | `python3` |
| `tests/ui_smoke.mjs` | タスク管理の操作（39 項目） | `node` + Playwright |
| `tests/ui_extension.mjs` | 拡張の署名〜記帳〜取り外し（30 項目） | `node` + Playwright |

すべて GitHub Actions（`.github/workflows/taskdeck.yml`）で走ります。
`build.sh` も、ZIP を作る前に上 2 つを実行します。落ちたら配布物を作りません。

## なぜ実ブラウザで動かすか

この製品は「ブラウザで開いて操作する」ことがすべてです。
関数単位のテストでは、次のような不具合が見つかりません。実際に見つけたものです。

- タブを閉じるのが速いとデータが飛ぶ（保存の遅延書き込み）
- ボードの「完了」列が常に空になる（絞り込みの条件が完了を除いていた）
- 入力のたびに再描画され、保存ボタンのクリックが取りこぼされる
- 保存済みデータを読む経路だけで初期化順が壊れる（初回インストールでは起きない）

いずれも「操作したら期待どおりになるか」を確かめて初めて分かりました。

## 書き方の決まり

- **見た目ではなく、結果を確かめる。** 「ボタンの色」ではなく「押したら完了列に移るか」
- **1 つの `check()` に 1 つの主張。** 失敗したときに、何が壊れたかがそのまま分かるように
- **ラベルは日本語で、仕様の文になるように書く。** テストの出力が、そのまま動作仕様の一覧になります
- **使い捨ての鍵を使う。** テストは本番の秘密鍵に触りません。テストのたびに鍵を作ります

## 実行

```bash
python3 taskdeck/tests/test_license.py
python3 taskdeck/tests/test_package.py
npm i playwright
node taskdeck/tests/ui_smoke.mjs
node taskdeck/tests/ui_extension.mjs
```

Playwright が入っていない環境では、Python のテストだけでも意味があります
（署名の食い違いは、そこで捕まります）。

## 出す前の確認

自動テストが通ったうえで、次を手で確かめます。

- [ ] 配布 ZIP を展開し、別のブラウザで開いて動くか
- [ ] 発行したキーで制限が外れるか
- [ ] 拡張パッケージを読み込めるか
- [ ] 前の版のバックアップ JSON を読み込めるか（互換性）
- [ ] 開発者ツールの「ネットワーク」に通信が出ないか
