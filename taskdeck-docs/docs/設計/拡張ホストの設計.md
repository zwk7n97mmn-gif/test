# 拡張ホストの設計

本体が拡張をどう扱うかの設計です。実装は `app/taskdeck.html` の 6.5 節にあります。
拡張を書く側の視点は [拡張API仕様](../仕様/拡張API仕様.md) を参照してください。

## 設計の目標

1. **本体を汚さない。** 拡張が 0 個のときの動きは、拡張機構が無かったころと同一であること。
2. **壊れても巻き込まれない。** 拡張のエラーで本体が止まらないこと。
3. **足したり外したりが自由。** 入れる・止める・外すが、その場で反映されること。
4. **勝手なコードが動かない。** 販売元が署名したものだけを実行すること。

## 3 つの拡張点

本体が持つ受け口は 3 つだけです。増やすときは慎重に決めます（増やしたら減らせないため）。

| 受け口 | 何が増えるか | 呼ばれるタイミング |
|---|---|---|
| `registerView` | サイドバー「拡張」欄の項目と、中央の画面 | その項目が選ばれて `render()` が走るたび |
| `registerTaskPanel` | タスク詳細パネルの下部の欄 | タスクの詳細を開くたび |
| `registerExport` | 「データの保存と読み込み」の書き出しボタン | ダイアログを開くたび |

登録された内容は 1 か所にまとまります。

```js
contributions = { views: [], taskPanels: [], exports: [] }
```

## 動かすまで

```
loadPlugins()                localStorage から読む
   └ activatePlugins()
        ├ contributions を空にする      ← 毎回まっさらから作り直す
        └ 有効な拡張ごとに
             ├ validatePackage()        形式・API版・署名の確認
             ├ new Function("api", code) で関数にする
             └ makePluginApi() を渡して実行  → 拡張が register…() を呼ぶ
```

`activatePlugins()` は**冪等**です。何度呼んでも同じ状態になります。
そのため、拡張の追加・停止・取り外し、ライセンスの変更のたびに、素直に呼び直しています。

### いつ呼び直すか

| きっかけ | 理由 |
|---|---|
| 拡張の追加・停止・取り外し | 登録内容が変わるため |
| ライセンスキーの登録・解除 | `api.entitled`（利用権）が変わるため。ここを忘れると、キーを入れても制限が外れない |

## 失敗の閉じ込め

拡張の失敗は、必ずその拡張の中で止めます。

| 起きたこと | どうなるか |
|---|---|
| 署名が合わない | その拡張は無効化され、一覧に理由が出る。他は動く |
| 読み込み中に例外 | 同上。例外の内容も一覧に出す |
| 画面を描く途中で例外 | その画面の場所にだけ赤い枠でメッセージ。サイドバーや他の画面は無事 |
| タスクパネルで例外 | その欄だけメッセージ。詳細パネルの他の項目は編集できる |
| 書き出しで例外 | ダイアログにメッセージ。データは壊さない |

「安全側に倒す」を徹底しています。疑わしい拡張は**自動で停止**し、利用者が再開を選べます。

## 利用権（entitlement）

拡張を使う権利は、ライセンスキーの中に入っています（`x: ["tax"]`）。

```
isEntitled(manifest) = ライセンスが有効 かつ x に manifest.entitlement（既定は id）が含まれる
```

権利がなくても拡張は動きます。ただし `api.trialLimit` に manifest の `trialLimit` が入り、
拡張はその件数で自分に制限をかけます。**評価と製品版で別のパッケージを配らない**ための設計です。

> 制限をかけるのは拡張自身です。本体は強制しません。
> 拡張は販売元が署名したものだけが動くので、この分担で足ります。

## 本体データへの触りかた

拡張から本体のタスクへ触れるのは、`api.tasks` の 4 つだけです。

- `list()` / `get(id)` … **複製**を返します。拡張が返り値を書き換えても本体には影響しません
- `create(partial)` … 評価版のタスク上限を本体側で確認します
- `update(id, patch)` … 更新できる項目を限定し、`updatedAt` は本体が付けます

拡張に `data` そのものを渡さないのは、拡張の不具合で保存データが壊れるのを避けるためです。

## 画面の描き直しについて

本体の `render()` は状態が変わるたびに走り、そのとき拡張の画面も描き直されます。
そのため、拡張の中で「入力途中の値」を DOM に置いたままにすると消えます。
**入力中の値は拡張側の変数に持ち、描き直しのたびに書き戻す**のが決まりです。

確定申告拡張では `draft`（入力中の仕訳）がこれにあたります。
また、金額を打つたびに全体を描き直すと、保存ボタンを押した瞬間にボタンが消えて
クリックが取りこぼされます。合計欄だけを差し替える形にしてあります。
（この不具合は実ブラウザのテストで見つかりました。同じ設計にするときは注意してください。）

## これから足すかもしれない拡張点

必要が出るまで足しません。足すときは ADR に理由を書きます。

- `registerQuickAddHandler` … 入力欄の記法を拡張が増やせるようにする
- `registerSettingsPane` … 拡張ごとの設定画面
- `on("tasks:changed")` … タスクの変更を拡張へ知らせる
