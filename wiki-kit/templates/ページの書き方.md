# ページの書き方

📍`🏠ホーム > ✏️wikiの編集方法 > ページの書き方`

---

このwikiにページを追加・編集するときのルールです。<br>
**書き始める前にひととおり読んでください。** 特に [⚠️ ハマりどころ](#pitfalls) は事故が多いところです。

> ℹ️ このページは**人向け**です。同じ内容を機械が扱う形にしたものが `CLAUDE.md`、
> 守れているかを確かめるのが `python3 scripts/wiki_lint.py` です。

## <a id="filename"></a>1. ファイル名の決め方

**ファイル名 ＝ READMEに貼る名称** にします。

| ルール | 例 |
| --- | --- |
| **絵文字は削除する** | README `👀画面設計手順` → ファイル `画面設計手順.md` |
| **絵文字以外の記号（`()` `【】` `-` `_` 等）はそのまま残す** | `検索コンポーネント(searchCond).md` |
| **Windowsで使えない文字（`/ : * ? " < > \|`）だけ置換する** | `時刻/時間隔(time)` → `時刻・時間隔(time).md` |

> 💡 本文中から**別の表記で**参照するのは構いません。
> 少なくとも1か所、ファイル名と揃った表記でREADMEに登録されていれば検査は通ります。

<br>

## <a id="folder"></a>2. どのフォルダに置くか

**READMEの見出し階層 ＝ フォルダツリー** です。

| ルール |
| --- |
| `##` 見出しがトップ階層のフォルダ。以降 `###` `####` の小見出しも**全てフォルダ**にする |
| フォルダ名もREADMEの見出し名に揃える。**絵文字は削除**、装飾用の `=` も削除 |
| ⚠️ 目次内のグループ名は**フォルダにしない** |

> 💡 迷ったら、**既にある似たページがどこにあるか**を見て合わせてください。

<br>

## <a id="readme"></a>3. READMEへの登録

```md
- [ページ名](フォルダ/ページ名.md) … 1行説明
```

| ルール |
| --- |
| リンクの表示名は**ファイル名と揃える**（絵文字は付けてOK） |
| `… ` 以降の説明文は**リンクに含めない** |
| 🚨 パスに `(` `)` やスペースが含まれる場合は、**リンク先を `<>` で囲む**（[理由](#pitfall-paren)） |

<br>

## <a id="content"></a>4. ページの中身の書き方

### パンくずリスト

**全ページの先頭（H1の直後）にパンくずを置きます。**

```md
# ページ名

📍`🏠ホーム > 見出し1 > ページ名`

---
```

> ℹ️ パンくずの各名称は **READMEの表記に揃えます**（絵文字も含めてREADMEどおり）。

### 目次と見出しアンカー

| ルール |
| --- |
| 🚨 **アンカーは見出し行の内側に置く**（`## <a id="x"></a>タイトル`）<br>別行に置くとHTMLブロック扱いになり、**直後の見出しが飲み込まれる**ことがある |
| 🚨 **自動生成IDは使わない**。絵文字・記号・大文字小文字の扱いが環境依存で、リンク切れになる |

### 出典の注記

そのまま転記したページ**以外**は、**何を根拠に書いたか**をパンくずの直後に明記します。<br>
読み手が「正式な仕様書」と「こちらで書き起こしたもの」を区別できるようにするためです。

| 根拠 | 書くこと |
| --- | --- |
| **ソースコードを読んで書き起こした** | ソースが正である旨と、推測が混じること |
| **定義ファイル・スキーマから起こした** | そちらが正である旨と、追従が必要なこと |
| **既存ページを機能単位で再構成した** | 実機確認していない箇所 |

## <a id="image"></a>5. 画像・動画の置き方

**`_image/` 配下に、ページの配置パス ＋ ページ名フォルダ**を掘ります。**1ページの画像は1フォルダにまとまります。**

```
_image/
  _HOME/                    ← README（ホーム）で使う画像はここ
    01_〔画像名〕.png
  〔フォルダ名〕/
    〔ページ名〕/            ← ページ名フォルダ
      01_〔画像名〕.png
      sub_01_〔画像名〕.png  ← サブグループは接頭辞かサブフォルダで
```

| ルール |
| --- |
| ファイル名は**ページ名由来の接頭辞を付けない**。`01_` `02_` の連番だけ |
| **複数ページから参照する共有画像**だけは、ページ名フォルダを作らず属するフォルダ階層の**直下**に置く |
| 🚨 **必ず相対パス**。`/_image/...` のルート起点はGiteaのファイルビューで解決されない |
| 🚨 パスにスペースや `(` `)` が含まれる場合は `<>` で囲む（`<img src="...">` はHTML属性なので不要） |

動画も同じ階層ルールで置きます。`<video>` の直後に**ファイルへの通常リンクも併記**してください
（再生できない環境でファイルビューから開けるようにするため）。

> 🚨 動画は**一度コミットするとgit履歴から消せません**。追加前に必ずサイズを確認してください。

## <a id="gitea-syntax"></a>6. Giteaで使える書き方

| 書き方 | 使えるか | メモ |
| --- | :-: | --- |
| **表（テーブル）** | ✅ | 仕様の羅列は基本これ |
| **mermaid** | ✅ | ` ```mermaid ` で囲む |
| **`<details>`** | ✅ | ⚠️ **`<div>` で囲まないと中身のMarkdownが解釈されない** |
| **`<img>` / `<video>`** | ✅ | `src` `width` `height` `alt` `controls` が通る |
| **コードブロック** | ✅ | 言語を指定するとハイライトされる |
| **JavaScript** | ❌ | サニタイズされる |
| **`<style>` / インラインCSS** | ⚠️ | 消える可能性がある。**色に意味を持たせない** |

### `<details>` の書き方

```md
<details>
  <summary>クリックで開閉</summary>
  <div>

ここに中身（空行を1行あけるのがポイント）

  </div>
</details>
```

## <a id="pitfalls"></a>7. ⚠️ ハマりどころ

### <a id="pitfall-paren"></a>① リンク先に `(` `)` やスペースがあると壊れる

Markdownのリンク記法は `)` で終わりと判断するため、**パスの途中の `)` で切れます**。

```md
❌ [一覧コンポーネント(listTable)](機能/一覧コンポーネント(listTable).md)
✅ [一覧コンポーネント(listTable)](<機能/一覧コンポーネント(listTable).md>)
```

> 💡 コンポーネント名・画像フォルダ名に括弧が入るので**頻発します**。

### ② 表のセルに `|` を書くと列が増える

エスケープで対応できますが、`\` を含む文字列は表現が難しいです。<br>
そういう内容は**表をやめて、箇条書き＋コードブロックにしてください**。

### ③ 見出しの自動生成IDに頼るとリンクが切れる

環境によって生成IDが変わります。**必ず `<a id="...">` を明示**してください。

### ④ 画像パスをルート起点で書くと表示されない

```md
❌ ![説明](/_image/〔フォルダ名〕/01_main.png)
✅ ![説明](../_image/〔フォルダ名〕/〔ページ名〕/01_main.png)
```

### ⑤ ページを移動したらリンクを直す

そのページを参照している**全ページ**とREADMEのリンクを直してください。<br>
どこから参照されているかは、Giteaの『コードを検索』で探せます。

## <a id="lint"></a>8. 書けたら検査する

```bash
python3 scripts/wiki_lint.py
```

ここまでのルールのうち、機械で見られるものは検査になっています。<br>
**投稿する前に実行してください。** CI でも同じものが走ります。

| 検査 | 見つかるもの |
| --- | --- |
| `links` | リンク先のページが無い |
| `wrapping` | 括弧や空白を含むリンクを `<>` で囲んでいない |
| `anchors` | 目次のジャンプ先が無い／使われていない |
| `anchor_placement` | アンカーが見出し行の外にある |
| `filenames` | 目次の表記とファイル名が食い違う |
| `orphans` | どこからも辿れないページ |
| `breadcrumbs` | 見出し・パンくずが無い |
| `images` | 画像・動画の参照先が無い／絶対パス |
| `image_layout` | 画像がページごとの置き場に無い |
| `details` | `<details>` が `<div>` で囲まれていない |
