# 〔wikiリポジトリ名〕

〔このwikiが何のためのものかを1〜2行で〕

- 目次兼トップページ: `README.md`
- **人向けの決まりごと**: `wikiの編集方法/ページの書き方.md`（本ファイルと同じ内容を、読み物として書いたもの）
- 決まりごとの検査: `python3 scripts/wiki_lint.py`

> ⚠️ 本ファイルと `ページの書き方.md` は**同じ決まりごと**を扱う。片方だけ直すとズレるため、
> 変更するときは両方を同じコミットで直す。

## ページ作成の制約

### 1. ファイル形式

- 各ページは md ファイルで作成する。

### 2. 命名規則

- **ファイル名と README に貼る名称を揃える。**
- 絵文字は削除する。
- 絵文字以外の記号（`()` `【】` `-` `_` 等）はそのまま残す。
- Windows で使用できない文字（`/ : * ? " < > |`）のみ置換する。
  - 例: `時刻/時間隔(time)` → `時刻・時間隔(time).md`

| README の表記 | ファイル名 |
| --- | --- |
| `👀画面設計手順` | `画面設計手順.md` |
| `検索コンポーネント(searchCond)` | `検索コンポーネント(searchCond).md` |
| `時刻/時間隔(time)` | `時刻・時間隔(time).md` |

> 本文中から別ページを**別の表記で**参照するのは構わない。
> 少なくとも 1 か所、ファイル名と揃った表記で登録されていればよい。

### 3. 配置パス

- README の見出し階層をそのままフォルダツリーにする。
- 目次（`## 🔖目次`）内のグループ名はフォルダにしない。
- `##` 見出しがトップ階層のフォルダ。以降 `###` `####` の小見出しも全てフォルダにする。
- フォルダ名も README の見出し名に揃える。絵文字は削除、装飾用の `=` は削除する。

```
はじめに/
  開発で意識すること/
    〔ページ名〕.md
〔機能名〕説明/
  共通/
    〔コンポーネント名〕.md
```

### 4. README のリンク

- ページを作成したら、README の該当リンクを実際の相対パスに更新する。
- `… ` 以降の説明文はリンクに含めない。
- パスに `(` `)` や空白が含まれる場合は、リンク先を `<>` で囲む
  （囲まないと Markdown のリンク記法が壊れる）。
  - 例: `[検索コンポーネント(searchCond)](<〔機能名〕説明/共通/検索コンポーネント(searchCond).md>)`

## 画像の配置

- 画像はリポジトリルートの `_image/` 配下に置く。
- `_image/` の中は **ページの配置パス ＋ ページ名フォルダ** を掘る。**1 ページの画像は 1 フォルダにまとまる。**
- ファイル名はフォルダで区別が付くので、ページ名由来の接頭辞は付けない。`01_` `02_` の連番だけ付ける。
- README（ホーム）直下で使う画像は `_image/_HOME/` に置く。
- 複数ページから参照する共有画像だけは、ページ名フォルダを作らず**属するフォルダ階層まで**に置く。

```
_image/
  _HOME/
    01_〔画像名〕.png
  〔フォルダ名〕/
    〔ページ名〕/
      01_〔画像名〕.png
```

- 参照は**相対パス**で書く。`/_image/...` のようなルート起点の絶対パスは Gitea のファイルビューで解決されない。
  - 深さ 2 のページ → `![説明](../_image/〔フォルダ名〕/〔ページ名〕/01_〔画像名〕.png)`
  - 深さ 3 のページ → `![説明](../../../_image/...)`
- パスに空白や `(` `)` が含まれる場合は `<>` で囲む。
- サイズを指定したい場合は `<img>` タグを使う（Gitea は `src` `width` `height` `alt` を通す）。

### 動画

- 動画も `_image/` 配下に、画像と同じ階層ルールで置く。
- Gitea は `<video>` タグを通す。`src` は画像と同じく**相対パス**。
- `<video>` の直後に**ファイルへの通常リンクも併記**する。再生できない環境でファイルビューから開けるようにするため。
- ⚠️ 動画はサイズが大きく、**一度コミットすると git 履歴から消せない**。追加前に必ずサイズを確認する。

## md ページのテンプレート

`wikiの編集方法/テンプレート/` にあります。用途に応じてコピーしてください。

| テンプレート | 用途 |
| --- | --- |
| `汎用ページ.md` | 迷ったらこれ |
| `手順ページ.md` | 作業手順・セットアップ手順 |
| `機能説明ページ.md` | 「この定義を書いたらこう動く」を説明する |
| `コンポーネント説明ページ.md` | 部品の仕様書 |

どのページも先頭は次の形にする。

````md
# タイトル名

📍`🏠ホーム > 〔経路〕 > タイトル名`

---
````

- `📍` はパンくずリスト（現在地）。ホームからそのページへ辿る経路を記載する。
- パンくずの各名称は README の表記に揃える（**絵文字も含めて README どおり**）。

### 出典の注記

転記元をそのまま写したページ以外は、**何を根拠に書いたか**をパンくずの直後に明記する。
読み手が「正式な仕様書」と「こちらで書き起こしたもの」を区別できるようにするため。

````md
> ℹ️ **このページはソースコードを読んで書き起こしたものです。**<br>
> 記載内容には**実装からの推測が混じります**。実際の挙動と食い違う場合はソースが正です。
> 気づいた方は修正をお願いします。
````

## README の見出しアンカー

- 目次からのジャンプは**明示アンカー方式**を使う。
- `## <a id="setup"></a>💻開発環境の構築手順` のように、アンカーは見出し行の**内側**に置く。
  - 別行に置くと HTML ブロック扱いになり、直後の見出しが飲み込まれる場合があるため。
- 自動生成 ID は絵文字・記号・大文字小文字の扱いが環境依存なので使わない。

## 決まりごとの検査

書いたら、投稿する前に次を実行してください。

```bash
python3 scripts/wiki_lint.py
```

| 検査 | 見つかるもの |
| --- | --- |
| links | リンク先のページが無い |
| wrapping | 括弧や空白を含むリンクを `<>` で囲んでいない |
| anchors | 目次のジャンプ先が無い／使われていない |
| filenames | 目次の表記とファイル名が食い違う |
| orphans | どこからも辿れないページ |
| breadcrumbs | 見出し・パンくずが無い |
| images | 画像・動画の参照先が無い／絶対パスになっている |
| image_layout | 画像がページごとの置き場に無い |
| details | `<details>` が `<div>` で囲まれていない |
| anchor_placement | アンカーが見出し行の外にある |
