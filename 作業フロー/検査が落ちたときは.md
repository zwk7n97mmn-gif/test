# 検査が落ちたときは

📍`🏠ホーム > 👷作業フロー > 検査が落ちたときは`

`python3 scripts/wiki_lint.py` が `NG` を出したときの読み方と直し方です。

<br>

## 🔖 どの検査が落ちた？

> このページの目次も兼ねています。

| 出た文言 | 意味 | 詳細 |
| --- | --- | --- |
| リンク先のページがある | リンク先が無い | [リンクまわり](#link) |
| 括弧や空白を含むリンクを <> で囲んでいる | 囲みが足りない | [リンクまわり](#link) |
| 目次のジャンプ先がそろっている | アンカーの過不足 | [目次まわり](#toc) |
| 目次の表記とファイル名がそろっている | 表示名とファイル名が違う | [目次まわり](#toc) |
| どのページも目次から辿れる | READMEに未登録 | [目次まわり](#toc) |
| 見出しとパンくずがある | 先頭の形が違う | [ページの先頭](#head) |
| アンカーが見出し行の内側にある | アンカーの位置 | [ページの先頭](#head) |
| 画像・動画の参照先がある | 参照先が無い | [画像まわり](#image) |
| 画像がページごとの置き場にある | 置き場が違う | [画像まわり](#image) |
| `<details>` の中身を `<div>` で囲んでいる | 囲みが足りない | [書き方まわり](#style) |
| 色に意味を持たせていない | 色で意味を表している | [書き方まわり](#style) |
| （どうしても通らない） | 検査を切りたい | [どうしても通らないとき](#offswitch) |

## <a id="link"></a>1. リンクまわり

### リンク先のページがある

リンク先のファイルが**実際に無い**ときに出ます。ページを消した・改名したのに、
リンクを直し忘れているのが原因です。

| 直し方 | いつ |
| --- | --- |
| リンクを直す | 移動・改名しただけのとき |
| リンクを消す | ページごと消したとき |

### 括弧や空白を含むリンクを <> で囲んでいる

パスに `(` `)` や空白が入るとき、囲まないと Gitea でリンクが切れます。

```md
- [部品(x)](<フォルダ/部品(x).md>)
```

> ⚠️ **書いた本人の画面では切れて見えないことがあります。** 見た目で判断しないでください。

<br>

## <a id="toc"></a>2. 目次まわり

### 目次のジャンプ先がそろっている

`](#xxx)` と `<a id="xxx"></a>` の**どちらかが無い**ときに出ます。

| 出方 | 原因 |
| --- | --- |
| 飛び先が無い | 見出し側のアンカーを書き忘れた |
| どこからも使われていない | 目次から行を消したのにアンカーを残した |

### 目次の表記とファイル名がそろっている

README の表示名とファイル名が食い違っています。**絵文字と装飾は名前に含めない**扱いです。

```md
[🔰はじめに](はじめに.md)              → はじめに.md
[時刻/時間隔(time)](<時刻・時間隔(time).md>)  → 時刻・時間隔(time).md
```

絵文字は落とし、使えない文字（`/` など）は `・` に置き換えて比べます。

> ℹ️ 同じページを**別の呼び方**で本文から参照するのは構いません。
> 1つでも一致する表記があれば通ります。

### どのページも目次から辿れる

README からも他のページからも辿れないページです。README に1行足してください。<br>
意図して置いているもの（下書きなど）は `wiki-lint.json` の `allow_orphan` に書きます。

<br>

## <a id="head"></a>3. ページの先頭

ページの先頭は必ずこの形にします。

```md
# ページ名

📍`🏠ホーム > 〔経路〕 > ページ名`

---
```

| 出た文言 | 直し方 |
| --- | --- |
| 1 行目が「# タイトル」でない | 1行目を `# ページ名` にする |
| パンくず（📍）が先頭付近に無い | 先頭6行以内に `📍` の行を置く |

### アンカーが見出し行の内側にある

アンカーは**見出しと同じ行**に置きます。

```md
## <a id="sec1"></a>1. 見出し
```

別の行に置くと HTML ブロック扱いになり、**直後の見出しが飲み込まれます**。

<br>

## <a id="image"></a>4. 画像まわり

| 出た文言 | 直し方 |
| --- | --- |
| 参照先が無い | 画像を置くか、パスを直す |
| ルート起点の絶対パスは Gitea で表示されない | `/_image/…` をやめ、相対パスにする |
| 置き場が違う | `_image/` ＋ ページの配置パス ＋ ページ名 に移す |

画像は**ページと同じ構成**で置きます。

```
製品/TaskDeck.md
_image/製品/TaskDeck/01_画面.png
```

> ⚠️ **別のページの画像フォルダを参照しないでください。**<br>
> そのページを消したときに、気づかないまま画像が消えます。ページを写して作ったときに起きがちです。

<br>

## <a id="style"></a>5. 書き方まわり

### `<details>` の中身を `<div>` で囲んでいる

囲まないと Gitea が中の Markdown を解釈せず、**表やリンクが生のまま出ます**。

```md
<details>
  <summary>クリックで開閉</summary>
  <div>

ここに中身（空行を1行あけるのがポイント）

  </div>
</details>
```

### 色に意味を持たせていない

`` `<span style="color: red;">` `` や `` `<font color="red">` `` で「ここが重要」を表すと出ます。

Gitea や GitHub は環境によってインラインCSSを落とします。落ちると赤が**ただの黒い文字**になり、
**重要だという意味ごと消えます**。

| 度合い | こう書く |
| --- | --- |
| 絶対にやってはいけない | `> 🚨 **【内容】**` |
| 気をつけること | `> ⚠️ **【内容】**` |
| 知っていると便利 | `> 💡 【内容】` |
| 補足 | `> ℹ️ 【内容】` |

> ℹ️ `` `<img width="900">` `` のように、**見た目に意味が乗らない属性**は使って構いません。

<br>

## <a id="offswitch"></a>❓ どうしても通らないとき

検査は `wiki-lint.json` で個別に切れます。ただし**切る前に本当に直せないか**を考えてください。

```json
{
  "checks": { "filenames": false }
}
```

| 手段 | 使いどころ |
| --- | --- |
| `allow_orphan` に足す | 意図して孤立させているページがある |
| `exclude` に足す | 規約の説明そのものなど、検査の対象外にしたいページ |
| `checks` で切る | その決まりを**このwikiでは採らない**と決めたとき |
