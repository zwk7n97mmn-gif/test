# 楽天アフィリエイト運用チーム

3 人のサブエージェントで、商品選定 → 記事作成 → 公開前チェックを回します。
Claude Code から `@rakuten-research` のように呼び出すか、「リサーチ担当に〜」と
指示すると担当が起動します。

## メンバー

| 担当 | ファイル | 役割 | 編集権限 |
|---|---|---|---|
| リサーチ | [`.claude/agents/rakuten-research.md`](../agents/rakuten-research.md) | 商品・キーワード・競合の調査と採否判定 | 調査メモの書き込みのみ |
| ライティング | [`.claude/agents/rakuten-writer.md`](../agents/rakuten-writer.md) | 調査メモをもとに記事・投稿を執筆 | 原稿の作成・修正 |
| チェック | [`.claude/agents/rakuten-checker.md`](../agents/rakuten-checker.md) | 公開前の検品と合否判定 | **読み取り専用**（自分では直さない） |

チェック担当にわざと編集権限を持たせていません。書いた本人が直すことで、
「指摘したつもり」で修正が漏れる事故を防ぎます。

## 流れ

```
1. リサーチ担当   →  調査メモ  (content/affiliate/research/<slug>.md)
        ↓  採用と判定した商品だけ渡す
2. ライティング担当 →  原稿      (content/affiliate/drafts/<slug>.md)
        ↓
3. チェック担当   →  判定 (合格 / 要修正 / 不可) と指摘リスト
        ↓  要修正ならライティング担当に差し戻し（2 に戻る）
4. 合格 →  公開
```

差し戻しは 2 往復までを目安にします。3 往復してもチェックが通らない題材は、
記事の問題ではなく商品選定の問題であることが多いので、リサーチ段階に戻します。

## ルールの優先順位

下にあるものほど強く、上書きします。

1. 各担当ファイルの本文（デフォルトの判断基準）
2. [`rules-common.md`](rules-common.md) — 3 人共通のルール
3. 各ファイル末尾の **「追加ルール（運用者記入欄）」**
4. その場での直接の指示

## ルールを足すとき

追記したい内容によって、書く場所を変えてください。

- **3 人全員に効かせたい**（禁止表現、トンマナ、案件ごとの前提）
  → [`rules-common.md`](rules-common.md) の「追加ルール」欄
- **1 人だけに効かせたい**（文字数、調査の深さ、判定の厳しさ）
  → その担当ファイル末尾の「追加ルール」欄
- **検品項目を増やしたい**
  → [`checklist.md`](checklist.md) に行を足す（チェック担当がそのまま使います）

書式は自由です。箇条書きで 1 行でも構いません。既存の記述と矛盾する場合は、
あとから追記されたルールが勝ちます。

## 埋めていない項目

料率・報酬の確定条件・支払い基準など、楽天側の規約や条件は変更されるため、
数値を書き込まずに空欄にしてあります。[`rules-common.md`](rules-common.md) の
「要確認パラメータ」に、公式の管理画面・規約で確認した値を入れてください。
埋まるまで、3 人とも「未確認」として扱い、その値に依存する判断を保留します。
