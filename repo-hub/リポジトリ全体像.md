# リポジトリ全体像

📍`🏠ホーム > 📁リポジトリ全体像`

---

## 📖 概要

どのリポジトリに何があるかの入口です。**まずここを見て、目的のリポジトリの README へ進んでください。**

リポジトリは 21 個あります。全部を覚える必要はありません。
自分の役割に関係するものだけを [🚪 役割別の入口](#role) から辿れば足ります。

> ⚠️ 本ページの内容は、共有された wiki（フォルダ構成・jinkyu_tools）とワークフロー定義から起こしたものです。
> 実態と違う箇所は直してください。一覧の正は `repos.json` で、本ページの表とは自動照合されます。

## 🗺️ ぜんたいの流れ

設計資料からシステムへ、データがどう流れるかです。

```
📄 設計資料                        🛠 データ化                      📦 製品
[jinkyu_doc]                     [jinkyu_tools]                  [jinkyu_src]
 ├ 画面設計（CRUD表）      ──→   20.CRUD表より画面構成json   ──→   _v2/data/ の JSON 定義
 ├ テーブル設計            ──→   30.DDL・コンポーネントjson  ──→   SQL/_v2/ の DDL
 ├ コード設計              ──→   [jinkyu_manager_code]       ──→   コード名称マスタ SQL
 └ メニュー・権限          ──→   [jinkyu_manager_menu]       ──→   メニューマスタ SQL
                                 [jinkyu_bat_definition_generator] ──→ バッチ定義 SQL
                                                                        │
                                                    毎時マージ           ▼
                                              [jinkyu_src_merged_json]  ← 実際の挙動はこちらの値
```

```
🧪 テスト                                        💬 問い合わせ
[jinkyu_e2e_test]  実行用の bat                  [syomuzimu] にイシューを立てる
        │                                                │ help-AI ラベル
        ▼                                                ▼
[jinkyu_playwright]  テスト本体                   AI が上記のリポジトリを読んで返信
        │  ← [jinkyu_playwright_generator] が枠を生成
        ▼
[jinkyu_test_result]  エビデンス
        │  ← [screenshot_comparator] で画面の差分を比較
```

## <a id="role"></a>🚪 役割別の入口

| あなたの役割 | まず見るもの | 次に見るもの |
| --- | --- | --- |
| **設計者**（画面・テーブルを設計する） | [jinkyu_doc] … 設計資料の置き場 | [jinkyu_tools] で SQL・JSON を生成 → [syomuzimu.wiki] の共通仕様 |
| **開発者**（実装する） | [jinkyu_develop_wiki] … 環境構築と開発ルール | [jinkyu_src] のコード → [jinkyu_json_schema] で定義の書き方 |
| **テスト担当** | [jinkyu_e2e_test] … 実行手順 | [jinkyu_playwright] のテストコード → [jinkyu_test_result] にエビデンス |
| **業務を知りたい人** | [jinkyu_knowledge_doc] … 業務知識・用語 | [syomuzimu.wiki] … 庶務事務の運用ルール |
| **v1 を知りたい人** | [jinkyu_v1_migration_skills] … v1↔v2 の対応 | [jinkyu_src] の SQL/DDL |
| **仕様を質問したい人** | [syomuzimu] にイシューを立てて `help-AI` ラベル | 返信は 10〜20 分。追加質問はコメント → ラベル再付与 |

## ⚠️ 迷いやすいところ

同じ情報が複数の場所にあるものです。**どちらが正か**を間違えると、調べ直しになります。

| 知りたいこと | 見るべき場所 | よくある間違い |
| --- | --- | --- |
| 画面の**現在の挙動** | [jinkyu_src_merged_json] | [jinkyu_src] のマージ前だけを見る。自動生成の上に手動上書きが乗るため、実効値は違う |
| 画面定義を**変更する場所** | [jinkyu_src] の `_v2/data/` | マージ後を直す。反映されない |
| **コード値**（区分値とその名称） | [jinkyu_manager_code] の JSON | Excel のコード一覧を探す。SQL と設計書 md はこの JSON から生成される |
| **テーブルの実際の列・型** | [jinkyu_src] の `SQL/` | テーブル定義書（Excel）。実 DDL が正 |
| **画面項目・CRUD** | [jinkyu_src_merged_json] | CRUD 表（Excel）が読めずに止まる。内容はマージ後の JSON に落ちている |
| **業務の用語・運用** | [jinkyu_knowledge_doc] | [jinkyu_develop_wiki] を探す。開発者向け wiki に業務知識は無い |
| **庶務事務の画面ルール** | [syomuzimu.wiki] | [jinkyu_develop_wiki] の一般論を適用する。庶務事務側の取り決めが優先 |

> 💡 **Excel が読めなくても、たいていは別の形で読めます。** 上表の「見るべき場所」は、
> どれも Excel ではなく JSON・DDL・Markdown です。Excel を開けないことを理由に
> 「確認できていない」で止める前に、こちらを当たってください。
