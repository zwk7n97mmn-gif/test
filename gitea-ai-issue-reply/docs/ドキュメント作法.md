# ドキュメント作法

📍`🏠ホーム > 📁Giteaイシュー自動返信キット > ドキュメント作法`

---

このリポジトリのドキュメントの書き方です。**他のリポジトリを同じ形に揃えるときの雛形**として使えます。

## 📄 ページの型

すべてのページを次の順で書きます。

```markdown
# ページ名

📍`🏠ホーム > 📁リポジトリ名 > ページ名`

---

## 📖 概要
（1〜3 行。このページが何のためのものか）

---

## 本文（見出しに絵文字を付ける）

---

## 👀 関連ページ
- [別のページ](別のページ.md) … 一言で何が書いてあるか
```

- **パンくず（📍）を必ず入れる。** 深い階層のページに直接飛んできた人が、位置を見失わないため
- **関連ページを必ず入れる。** 行き止まりのページを作らない。1 ページ 1 主題にすると、自然に相互リンクが要る
- **リンクには「… 一言」を添える。** 開かないと分からないリンクは踏まれません

## 🔣 使う記号

| 記号 | 使いどころ |
| --- | --- |
| 📦 | ツリーの根（リポジトリ名） |
| 📂 📜 | フォルダ／ファイル |
| ⚠️ | 読み飛ばすと事故になること |
| ⛔ ~~取り消し線~~ | 廃止された手順。**消さずに残し、移行先を併記する**（古い手順書を見ている人が辿り着けるように） |
| ※ | 前提や補足（`※要uv sync` など） |
| 👉 | 詳細ページへの誘導 |

## 🌲 ツリーの書き方

```
📦リポジトリ名 ※照合しない（書き方の例）
 ┣ 📂フォルダ
 ┃ ┣ 📜ファイル.sh            … 何をするか
 ┃ ┗ 📜ファイル2.sh
 ┣ 📂別のフォルダ　　　　※要uv sync
 ┗ 📜README.md
```

- **名前の後ろに「… 説明」または「※注記」を付けてよい。** 検査は名前だけを見ます
- **実体ではないツリー**（配置後の姿、他リポジトリの構成など）は、1 行目を
  `📦名前 ※照合しない` にします

> ⚠️ **同じツリーを 2 か所に手で書かない。** どうしても必要なら、
> `scripts/check_tree.py` のような検査を入れてください。
> 手で写したツリーは、片方だけ更新されて必ず離れていきます。

## 📊 表の使いどころ

| 書きたいもの | 形 |
| --- | --- |
| フォルダに何が入っているか | フォルダ / 何が入っているか / 備考 の 3 列 |
| ツールの入出力 | 入力 / 生成物 の 2 行（入力が複数なら 入力① 入力②） |
| 選択肢の比較 | 案 / 評価 の 2 列。**却下した案も残す**（同じ議論を繰り返さないため） |
| 症状と対処 | 症状 / 確認すること の 2 列 |

## 🖼️ 画像

長い画像は折りたたみます。本文の流れを切らないためです。

```markdown
<details>
  <summary>🖼️ イメージ</summary>
  <div>

![説明](../_image/ページ名/画像.png)

  </div>
</details>
```

## ✅ 機械で守れることは機械で守る

人が気をつけるだけの決まりは、いつか必ず破られます。次は検査にしてあります。

| 決めごと | 検査 |
| --- | --- |
| ドキュメントのツリーと実体が一致していること | `scripts/check_tree.py` |
| 参照リポジトリの一覧が 3 か所で一致していること | `scripts/check_sync.py` |
| ページ間のリンクが切れていないこと | （リンク切れ検査を足すならここ） |

`bash tests/run_all.sh` に入れておけば、直し忘れたままマージされることがなくなります。
