# セットアップ

📍`🏠ホーム > 📁Giteaイシュー自動返信キット > セットアップ`

---


Gitea のリポジトリに置いて動かすまでの手順です。所要 30 分ほど。

## 必要なもの

| もの | 用途 |
| --- | --- |
| Gitea（Actions 有効）と act_runner | ワークフローの実行 |
| Claude の契約プランの OAuth トークン | 返信の生成（**契約プランの枠を使う。従量課金にしない**） |
| bot 用のアカウントとトークン | コメントの投稿・ラベルの操作 |
| 参照リポジトリを読める PAT | 調査対象の取得（同一 bot のトークンで足りることが多い） |

ランナーには `git` / `jq` / `curl` / `node`（npm）が要ります。`ubuntu-latest` 相当のイメージなら入っています。

## 1. ファイルを配置する

イシューを立てるリポジトリに、次の形で置きます。

```
<リポジトリ>/
├── .gitea/
│   ├── workflows/ai-issue-reply.yml     ← workflows/ai-issue-reply.yml
│   ├── scripts/                          ← scripts/ 一式
│   └── ISSUE_TEMPLATE/ask_ai.yaml        ← issue-templates/ask_ai.yaml
├── .claude/skills/issue-ai-reply/SKILL.md ← skills/issue-ai-reply/SKILL.md
├── refs.json
└── .gitattributes
```

同梱の `scripts/install.sh` で配置できます。

```bash
bash scripts/install.sh /path/to/your-repo
```

> **`.gitattributes` を必ず入れてください。** Windows で編集したワークフローやシェルスクリプトが
> CRLF のままコミットされると、Linux のランナーが行末の CR まで引数に含めて失敗します
> （`set: pipefail\r: invalid option name` の形で出ます）。

## 2. ラベルを作る

リポジトリのラベルに **`help-AI`** を追加します（名前を変える場合はワークフローの `TRIGGER_LABEL` も変更）。

## 3. Secrets を登録する

リポジトリの設定 → Actions → Secrets に登録します。

| 名前 | 中身 |
| --- | --- |
| `CLAUDE_CODE_OAUTH_TOKEN` | Claude の契約プランで発行した OAuth トークン |
| `BOT_TOKEN` | bot アカウントのアクセストークン（対象リポジトリの issue write 権限） |
| `BOT_LOGIN` | bot のログイン名。自分の過去返信を見分けるのに使う |
| `REF_TOKEN` | 参照リポジトリを読める PAT（read 権限） |

> **`ANTHROPIC_API_KEY` は登録しないでください。**
> API キーは**使った分だけ請求される従量課金**です。契約プランの枠内で収めるなら OAuth トークンを使います。
> 両方が設定されていると課金される側で動く可能性があるため、
> `run_claude.sh` は両立を検出したら**起動せずに止まります**。
>
> 枠を使い切ったときは、課金されるのではなく**その回の返信が失敗します**。
> コメントにはリセット時刻（JST）と再実行の方法が書かれます。

> **参照リポジトリを増やすときは、先に bot の権限を確認してください。** private リポジトリでは
> bot がコラボレータでないと clone が `Not found`（権限不足と同じ文言）で失敗します。

## 4. 参照リポジトリを設定する

`refs.json` を書き換えます。ここが唯一の設定箇所です。

```json
{
  "repos": [
    { "path": "src",  "repo": "your-org/your-app",   "ref": "main", "description": "実装コード" },
    { "path": "docs", "repo": "your-org/your-docs",  "ref": "main", "description": "設計書",
      "sparse": ["/*", "!*.xlsx", "!*.xlsm", "!*.docx", "!*.zip"] },
    { "path": "wiki", "repo": "your-org/your-app.wiki", "ref": "main", "description": "開発方針" }
  ]
}
```

| キー | 意味 |
| --- | --- |
| `path` | 配置先のディレクトリ名。**SKILL.md に書く名前と一致させる** |
| `repo` | `owner/repo`。Gitea の wiki は `owner/repo.wiki` |
| `ref` | ブランチ。参照データなので `main` を追う（固定すると古い内容で回答してしまう） |
| `sparse` | 取得しないファイルの指定。AI が開けない形式（Excel・Word 等）を落とすと、時間とディスクを節約できる |

書き換えたら、**3 か所の一覧が食い違っていないか**を確かめます。

```bash
python3 scripts/check_sync.py
```

## 5. SKILL.md を自分のプロジェクトに合わせる

`skills/issue-ai-reply/SKILL.md` の「前提環境」の表を、`refs.json` の `path` と揃えます。
`<!-- ここから -->` 〜 `<!-- ここまで -->` で囲ってある部分です。

プロジェクト固有の調査ルール（読む順番の例外、領域ごとの正典、命名規則など）があれば、
ファイル末尾のコメント位置に追記してください。**追記したら `docs/運用仕様.md` にも同じことを書きます。**

## 6. 動作を確認する

1. テンプレート「AIに質問する」からイシューを作る
2. 2〜3 分で「調査中です」のコメントが付く
3. 10〜20 分で返信に書き換わり、`help-AI` ラベルが外れる

コメントが付かないときは [トラブルシュート](トラブルシュート.md) を見てください。

## 手元での確認

Gitea に置く前に、部品だけなら手元で動かせます（通信しません）。

```bash
bash tests/run_all.sh          # 全テスト
DRY_RUN=1 GITEA_API=https://gitea.example.com/api/v1/repos/org/repo \
  bash scripts/gitea_api.sh create-comment 1 body.md   # 送信せず要求内容だけ表示
```
