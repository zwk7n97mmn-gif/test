# フォルダ構成

📍`🏠ホーム > 📁Giteaイシュー自動返信キット > フォルダ構成`

---

## 📦 各フォルダに何が入っているか

| フォルダ / ファイル | 何が入っているか | 備考 |
| --- | --- | --- |
| **workflows** | **Gitea Actions のワークフロー定義**。<br>ラベル付与で起動し、調査から返信までを実行する。 | 配置先 `.gitea/workflows/` |
| **skills** | **AI 向けの実行指示**（調査手順・返信の書式）。<br>👉 [詳細ページ](運用仕様.md) | 配置先 `.claude/skills/` |
| **issue-templates** | **イシューテンプレート**。<br>このテンプレートから作成すると `help-AI` ラベルが自動で付く。 | 配置先 `.gitea/ISSUE_TEMPLATE/` |
| **scripts** | **各処理の実体**。判定・取得・プロンプト組み立て・API 呼び出し・配置。<br>ワークフローからはこれらを呼ぶだけにしてある。 | 配置先 `.gitea/scripts/` |
| **docs** | **人向けのドキュメント**（本ページを含む）。 | 配置しない |
| **tests** | **全部品のテスト**。外部への通信はしない。<br>👉 [下記の詳細](#tests) | 配置しない |
| **refs.json** | **参照リポジトリの一覧**。移植時に書き換えるのはここだけ。 | 配置先 リポジトリ直下 |

<br>

> ファイルを増やしたり名前を変えたりしたら、ここも直してください。直し忘れは
> `bash tests/run_all.sh` で失敗として出ます。

## 📥 配置するとどうなるか

`scripts/install.sh` を実行すると、配置先のリポジトリは次の形になります。

```
📦your-repo ※照合しない（配置後の姿であり、このリポジトリの実体ではないため）
 ┣ 📂.gitea
 ┃ ┣ 📂workflows
 ┃ ┃ ┗ 📜ai-issue-reply.yml
 ┃ ┣ 📂ISSUE_TEMPLATE
 ┃ ┃ ┗ 📜ask_ai.yaml
 ┃ ┗ 📂scripts
 ┣ 📂.claude
 ┃ ┗ 📂skills
 ┃   ┗ 📂issue-ai-reply
 ┃     ┗ 📜SKILL.md
 ┣ 📜refs.json
 ┣ 📜check-tree.json
 ┗ 📜.gitattributes
```

`docs` と `tests` は配置しません。キット側に残し、**元をたどれる場所**として使ってください。

## <a id="tests"></a>🧪 tests

外部への通信をせずに、全部品を確かめます。`git` と `claude` は偽の実行ファイルに差し替え、
Gitea API は `DRY_RUN` で要求内容だけを確認します。

| ファイル | 何を確かめるか |
| --- | --- |
| `test_gate.sh` | ラベル単独／複数同時／別ラベル追加／PR／ラベル無しの各場合の起動可否 |
| `test_clone_refs.sh` | 浅い取得、失敗しても続行、`.git` の削除、トークンを出力しないこと |
| `test_build_prompt.sh` | 本文・コメントの埋め込み、自分の過去返信の識別、取得結果の受け渡し |
| `test_gitea_api.sh` | メソッドと URL、本文の JSON 化、トークンを出さないこと |
| `test_run_claude.sh` | 引数の組み立て、フラグ検証、利用上限の検出、課金ガード |
| `test_check_sync.py` | 参照一覧（3 か所）の食い違い検出 |
| `test_vendored.sh` | 配布元（check-tree）と同じ内容か・ツールが動くか |
| `test_layout.sh` | 配置後に動くか、YAML が妥当か、呼ぶスクリプトが揃っているか |

```cmd
bash tests/run_all.sh
```
