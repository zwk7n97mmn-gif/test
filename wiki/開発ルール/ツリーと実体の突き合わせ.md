## <a id="why"></a>1. なぜ要るか

構成図は**書いた瞬間から古くなります**。

| よくあること | 結果 |
| --- | --- |
| ファイルを足したが図に足さない | 図に無いファイルが増える |
| ファイルを消したが図に残す | 無いファイルを探して時間を溶かす |
| 改名したが図は旧名のまま | 検索しても出てこない |

> 🚨 **古い構成図は、無いより悪いです。**<br>
> 読む人は図を信じて動きます。信じられない図なら消したほうがまだ害がありません。

<br>

---

## <a id="write"></a>2. 書き方

構成図はコードブロックに書きます。**インデントで階層**を表し、フォルダは末尾に `/` を付けます。

```
はじめに/
  このwikiの読み方.md
  用語集.md
作業フロー/
  ページを追加する.md
```

| 決まり | 理由 |
| --- | --- |
| フォルダは `/` で終える | ファイルと見分けるため |
| 説明は書いてよい | 突き合わせは名前だけを見る |
| 図は**1ページに何枚あってもよい** | 章ごとに部分図を貼れる |

<br>

---

## <a id="run"></a>3. 確かめ方

```bash
python3 check_tree.py
```

図に書いてあるのに**無い**もの、実際にあるのに**図に無い**ものを並べます。

| 出方 | 意味 |
| --- | --- |
| 実体が無い | 消した／改名したのに図が古い |
| 図に無い | 足したのに図に書いていない |

<br>

---

## <a id="ignore"></a>4. 見ないもの

**追跡していないファイル**は最初から対象外です。

| 対象外 | 理由 |
| --- | --- |
| `.gitignore` に書いたもの | 一時ファイル・生成物は図に書かない |
| `.git/` の中 | 図に書く意味が無い |
| 設定で除外したもの | 巨大な生成物など |

> ⚠️ **入れたばかりのファイルも対象に入れてください。**<br>
> コミット済みのものだけを見ると、**今作ったファイルが「図に無い」ではなく
> 「そもそも見えない」**扱いになり、検査をすり抜けます。
