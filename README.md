# repo-hub — リポジトリ横断の入口ページ

📍`🏠ホーム > 📁repo-hub`

---

## 📖 これは何か

リポジトリが 20 個以上あると、**どこに何があるかを覚えている人にしか触れない**状態になります。
その入口になる 1 ページと、内容が実態から離れないようにする検査です。

| ファイル | 役割 |
| --- | --- |
| **[リポジトリ全体像.md](リポジトリ全体像.md)** | wiki に置く入口ページ。一覧・データの流れ・役割別の入口・迷いやすいところ |
| **repos.json** | リポジトリ一覧の**唯一の正**。増減はここを直す |
| `scripts/check_repos.py` | repos.json と入口ページの表・リンク定義を照合する |
| `scripts/check_links.py` | 参照リンクの定義漏れ・相対リンクの切れを検出する |
| `tests/` | 上 2 つの検査そのもののテスト |

<br>

## 🚀 使いかた

### 1. Gitea の URL を入れる

`リポジトリ全体像.md` の末尾にリンク定義が 21 行あります。
そこと `repos.json` の `gitea_base` に入っている `〔GiteaのURL〕` を置き換えるだけで、
ページ内の全リンクが繋がります。

```bash
sed -i 's|〔GiteaのURL〕|https://your-gitea.example.com/gitea|g' リポジトリ全体像.md repos.json
```

### 2. wiki に置く

`リポジトリ全体像.md` を wiki リポジトリの直下に置きます。
既存の `フォルダ構成.md` `jinkyu_tools.md` と同じ階層に置く前提でリンクしてあります。

### 3. 内容を実態に合わせる

本ページの内容は、共有された wiki 2 ページとワークフロー定義から起こしたものです。
**リポジトリの説明・役割・「迷いやすいところ」は、実態と突き合わせて直してください。**

### 4. 検査する

```bash
bash tests/run_all.sh
```

リポジトリを増減したら `repos.json` と入口ページの両方を直します。
片方だけだと検査が落ちるので、**直し忘れたまま気づかない状態にはなりません**。

## 🧩 なぜ一覧を JSON で持つのか

同じ一覧が複数の場所に現れるためです。いま分かっているだけでも 3 か所あります。

| 場所 | 何のための一覧か |
| --- | --- |
| wiki の入口ページ | 人が読む |
| AI 返信の `refs.json` | AI が読むリポジトリを取得する |
| ワークフローの clone ステップ | 実際の取得処理 |

手で写すと必ず離れていきます。**1 か所を正とし、他はそこから作るか、突き合わせて検査する**のが、
唯一この規模で保てるやり方だと考えています。

将来的には `repos.json` から AI 返信キットの `refs.json` を生成する形にもできます
（同じ `id` を使っているため、対応づけは取れています）。
