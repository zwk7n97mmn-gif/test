# 🎬 Kirinuki Studio

**スマートフォンだけで完結する**動画編集ツール。
素材を**解析**して、**字幕・カット編集・音声処理**を自動で付与し、**サムネイル**と**SNS キャプション**を作り、
そのまま SNS アプリへ**共有**できます。

- ビルド不要・**依存パッケージゼロ**（素の ES Modules）
- 動画はブラウザ内でのみ処理され、**外部に送信されません**（外部 STT を明示的に設定した場合を除く）
- ホーム画面に追加すればアプリのように起動し、**電波が無くても**編集できます
- 設計書: [`docs/DESIGN.md`](docs/DESIGN.md) ／ 手動テスト手順: [`docs/QA.md`](docs/QA.md)

```bash
npm start      # http://localhost:8080
npm test       # 153 件の単体テスト（node --test / 依存ゼロ）
```

> 動作要件: iOS Safari 17+ / Android Chrome 116+ / デスクトップ Chrome・Edge・Safari。
> `file://` では動きません（ES Modules のため）。

---

## スマートフォンでの使い方

1. ブラウザで開き、メニューから**「ホーム画面に追加」**
2. アイコンから起動 → **動画を選択**（写真アプリから選べます）
3. 解析が自動で走り、**「自動処理」**で字幕・カット・音声をまとめて適用
4. 各タブで仕上げ
5. **「📤 共有」**から TikTok / Instagram / X へ直接送る

画面下部のタブで機能を切り替えます。すべての操作は指だけで完結します。

## できること

| 機能 | 内容 |
|---|---|
| **素材解析** | シーン切替点・発話区間・無音区間・ラウドネス・フレーム品質を自動抽出しタイムラインに可視化 |
| **字幕の自動付与** | 発話区間からタイムコードを自動生成。STT を設定すればテキストまで自動（下記参照） |
| **編集の自動付与** | 無音の自動カット（または倍速化）。前後パディング・最小クリップ長を調整可能 |
| **音声の自動付与** | ラウドネス正規化・BGM の自動ダッキング・フェードイン/アウト |
| **サムネイル作成** | 品質スコア上位のフレームを自動抽出 → テキストを載せて 1280×720 PNG |
| **キャプション作成** | 字幕・尺・シーンから X / Instagram / YouTube / TikTok 向けの投稿文（文字数上限を厳守） |
| **書き出し** | 字幕焼き込み **MP4**・SRT・WebVTT・サムネイル PNG・プロジェクト JSON |
| **共有** | 動画・画像・投稿文を SNS アプリへ直接送信（Web Share API） |

## 書き出しの仕組み

**WebCodecs** でフレームを 1 枚ずつエンコードし、**自前の MP4 多重化**でファイルを組み立てます。
音声は `OfflineAudioContext` でカット・音量・ダッキングを適用して一括生成します。

これにより、**再生時間に縛られず、画面ロックやアプリ切り替えでも成果物が壊れません**
（従来の `MediaRecorder` 方式は「再生しながら録画」するため、スマートフォンでは致命的でした）。

- コーデックは H.264 / AAC を優先。持たない環境では VP9 / Opus を MP4 に収めます
- WebCodecs 非対応の環境では `MediaRecorder`（実時間）へ自動的に退避します
- 書き出し中は画面が消えないようにします（Screen Wake Lock）
- 所要時間は出力尺のおよそ 1〜2 倍（フレーム取得のシークが支配的）

## キーボード操作（デスクトップ）

| キー | 動作 |
|---|---|
| `Space` | 再生 / 一時停止 |
| `←` `→` | 1 フレーム移動（`Shift` で 1 秒） |
| `Home` `End` | 先頭 / 末尾へ |
| `S` | 再生位置でクリップを分割 |
| `Ctrl + Z` / `Ctrl + Shift + Z` | 元に戻す / やり直す |
| `1` – `7` | パネル切替 |
| `?` | ショートカット一覧 |

タイムラインはフォーカスすると矢印キーで操作できます（`role="slider"`）。
主要な文字色のコントラスト比 4.5:1 以上、タップ領域 44px 以上をテストで機械検証しています。

## 文字起こし（STT）について

ブラウザ単体では音声認識ができません（Web Speech API はマイク入力専用で、ファイルを渡せません）。
そのため 2 つの方法を用意しています。**存在しないテキストを creative に埋めることはしません。**

| 方法 | 通信 | 生成される内容 |
|---|---|---|
| **発話区間のみ**（既定） | なし | 字幕の**開始・終了時刻のみ**。テキストは「要入力」バッジ付きの空欄 |
| **外部 STT** | あり | タイムコード＋**テキスト**（OpenAI 互換 `/v1/audio/transcriptions`） |

API キーは**タブのメモリ上にのみ保持**し、保存も送信先以外への送出も行いません。

---

## 端末に保存されるもの

| 保存先 | 内容 |
|---|---|
| localStorage | 編集内容・解析結果（自動保存） |
| OPFS | 素材の動画ファイル（600MB まで／タブが破棄されても続きから再開するため） |
| 保存しない | STT の API キー |

## 制約

1. 書き出しは出力尺の 1〜2 倍の時間がかかります（さらなる高速化には MP4 デマルチプレクサが必要）。
2. 音声認識テキストは外部 STT 設定時のみ。
3. `decodeAudioData` が対応しないコーデックの素材は**映像のみモード**へ縮退します。
4. 極端に大きい素材（数 GB）はメモリ不足になることがあります。その場合は理由を表示します。

## 構成

```
index.html / manifest.webmanifest / sw.js
src/
  core/     解析・編集判断・整形・MP4 多重化（DOM 非依存の純粋関数 = テスト対象）
  media/    WebCodecs / WebAudio / Canvas / OPFS / 共有（副作用）
  ui/       ビュー
test/       node --test（依存ゼロ）
docs/       設計書・QA 手順
```

プレビューと書き出しは同じ描画・音声プラン生成コードを共有しているため、**画面で見たものがそのまま出力されます**。
